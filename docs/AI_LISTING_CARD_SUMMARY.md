# 판매글 목록 카드 AI 핵심 요약

## 목적과 화면

사용자가 판매글들을 비교할 때 “어떤 제품인지” 빠르게 파악하도록, 기존 상세 하단의 긴 요약을 카드용 1~2문장·전체 90자 이내로 변경했다. 제목 아래에 두 줄까지만 표시하고 전체 짧은 문구는 카드의 접근 가능한 텍스트에도 남긴다. 화면 폭에 따라 글 일부가 생략될 수 있다.

- 로그인 회원: ACTIVE 목록 카드에 저장된 문구와 생성·갱신 상태를 표시한다.
- 비회원: 기본 공개 목록은 계속 제공하며 AI 영역에는 로그인 안내만 표시한다. 이력 기반 문구나 실제 생성 상태는 응답에 포함하지 않는다.
- 상세: 제품 사양·전체 타임라인을 제공하고, 판매자에게만 `AI 카드 요약 관리`에서 짧은 문구·상태·재생성 버튼을 제공한다. RESERVED 글은 목록에 없지만 판매자가 상세에서 상태를 관리할 수 있다.

## 요청 흐름

1. 게시 완료 또는 관련 정보 수정 이벤트가 R09/R10의 비동기 생성 요청을 접수한다.
2. 작업자가 공개 허용 제품 정보와 전체 누적 핵심 이력으로 Gemini에 짧은 요약을 요청한다. 이전 소유자·정정·무효·미검토 기록의 입력 경계는 유지한다.
3. 1~2문장·90자 제한과 개인정보·근거 숫자·등록 날짜·작성 규칙 반복 여부를 검증한다. 생성 전후 버전·자료 지문이 동일할 때만 저장한다.
4. `GET /api/v1/listings`가 기존 페이지 쿼리에서 저장된 상태·문구를 함께 읽는다. 응답의 `aiSummary`는 `status`, `text`, `outdated`만 제공하며 카드별 이력 조회·AI 호출은 없다. 인증 정보로 회원 여부를 판단한다.
5. 화면은 생성 중 페이지를 3초 간격으로 최대 20회, 이후 및 완료 상태에서는 15초 간격으로 묶어서 조회한다. 숨긴 탭에서는 중지하고 로그아웃·화면 이동 때 문구와 툴팁을 지운다. 갱신 실패 때도 AI 문구를 지운다.

`aiSummary` 예시:

```json
{"status":"READY","text":"18GB 메모리 모델로, 정정된 점검 기록이 있습니다.","outdated":false}
```

제품 사실 버전이 달라진 문구는 숨긴다. 판매 조건만 바뀐 동일 제품 사실의 이전 문구는 `outdated=true`로 구분한다. 종료·소유권 변경·보관 제품은 목록에서 제외하며 생성 완료 시에도 공개 조건을 재검사한다.

## 기존 데이터 전환

새 정식 Flyway `V2026102802`는 제품 이력 `V2026102801` 다음에 `summary_format_version`을 추가한다. 기본값 0인 기존 긴 문구를 DB에서 보존하고, 화면 응답에서는 숨긴다. 백그라운드 조정기가 공개 조건을 만족하는 기존 READY 문구를 카드 형식으로 한 번 접수한다. 검증에 성공한 결과만 버전 1로 저장하며 DB도 90자 제한을 검사한다.

과거 demo 카드 요약 `V2026102702` 원문은 `docs/history/archive/V2026102702__version_listing_card_summary.sql.txt`에 보관한다. #57 이후 정식 ownership은 `2803`·`2804`이며 카드 요약 스키마는 일반 `V2026102802`가 담당한다. 현행 demo의 `2708`은 새 시연 DB용이며 과거 `2702`의 적용 기록을 자동 대체하지 않는다. 새 시연 DB `${java.io.tmpdir}/pastport-sale-draft-general-r02`를 사용한다. 과거 demo 카드 요약 `2702` 및 시험용 ownership `2702.1` 적용 DB의 자동 전환은 지원하지 않으며 기존 DB·이미지·사용자 데이터는 삭제하거나 변환하지 않는다.

기존 FAILED 결과는 서버 재시작이나 목록 조회로 자동 재시도하지 않는다. 외부 호출 실패·쿨다운·실행 수 제한은 R09/R10 정책을 유지하고 판매자가 재생성할 수 있다. 이미 대기·처리 중인 작업은 중복 접수하지 않는다.

## 확인 방법과 범위

- 회원 목록에서 짧은 문구, 비회원 응답에서 `LOGIN_REQUIRED`와 `text:null`을 확인한다.
- 기존 긴 READY 요약은 화면에서 숨겨지고 새 형식으로 교체되는지 확인한다.
- 판매 등급 수정 시 갱신 표시 후 새 문구가 적용되고, 제품 사실 변경 시 이전 문구가 숨겨지는지 확인한다.
- 상세 하단의 긴 공개 블록이 없어지고 판매자 관리 영역에서 재생성할 수 있는지 확인한다.
- 전체 타임라인·제품 사양은 원래 화면에서 확인한다. 짧은 문구는 원천 기록 전체를 대체하지 않으며 정규식 검증만으로 의미 정확성을 완전히 보장하지 않는다.

`HistoryService`의 사용자 이력·사양 추가·정정·무효 처리는 `facts_version` 증가와 `ProductFactsChanged` 발행을 연결했다. [저장 후 AI 갱신](AI_HISTORY_REFRESH_INTEGRATION.md)을 참고한다. 향후 문서 확정·소유권 이전·공개 범위 변경을 별도 경로에서 저장한다면 같은 버전·이벤트 계약을 연결해야 한다. 데모의 샘플 이력과 실제 이력 조회의 검증 범위를 구분한다.

## 이번 변경의 검증 기록

- 최신 main 통합 후 `clean spotlessCheck test build`: 641개 중 605개 성공, 환경 조건으로 36개 제외, 실패·오류 없음.
- 별도의 PostgreSQL 테스트 DB: 요약 HTTP·목록 HTTP·기존 데이터 전환·실제 이력 조회/API 통합 69개 성공. 테스트 DB는 종료 후 제거했다.
- 과거 구현 당시에는 정식 이력 `V2026102801` 이후 경로와 기존 demo 카드 요약 `V2026102702` 보존 경로를 검증했다. 후자는 현재 지원 계약에서 퇴역했다. 현재 일반 및 일반+demo fixture 경로의 검증은 [H40 일반 기준 복구 결과](history/h40-general-authority-result.md)를 따른다.
- 구현 당시 실제 Gemini로 공개 샘플 세 종류(전체 이력·빈 이력·미검토/무효 이력)를 각각 한 번 생성해 짧은 형식 검증을 통과했다. 이번 main 통합 검증은 외부 AI를 호출하지 않았으며, 모든 향후 생성의 의미·형식 성공률을 보장하는 결과는 아니다.
- 별도 로컬 DB와 가짜 AI를 이용한 브라우저 검사에서 카드 표시, 상세 이동, 등급 수정 후 갱신 중 표시와 새 문구 교체를 확인했다.

실제 모델을 사용한 대표 이력별 문구·근거 검사는 [제품 AI 실제 모델 품질 확인](AI_LIVE_QUALITY.md)에 정리한다. 짧은 형식의 통과와 문장 의미의 정확성을 별도로 확인한다.
