# R01~R07 판매글 작성·임시저장·미리보기·게시·목록·관리

현재 소유자가 보유 제품과 사진을 선택하고 작성 중인 판매 내용을 서버에 비공개로 저장한다.
필수 항목이 비어 있어도 저장할 수 있으며, 입력된 값과 사진 소속·소유권은 검사한다.
저장은 사용자가 임시저장·미리보기·게시를 눌렀을 때 수행한다. 게시는 확인 창에서 동의한 뒤 현재 내용을 먼저 저장한다.

기준은 [요구사항의 SALE-01·SALE-03](REQUIREMENTS.md)과 [ERD의 listing_drafts·draft_images](ERD.md)다.

## API

공개 목록과 목록용 대표 사진은 비회원도 조회할 수 있다. 나머지 경로는 인증이 필요하다. 초안·게시 요청은 현재 소유자 전용이고, 게시된 상세·사진은 로그인한 다른 회원도 조회할 수 있다.
성공 응답은 공통 `ApiResponse` 형식을 사용하고, 초안 및 사진 응답에 `Cache-Control: no-store`를 적용한다.

| Method | 경로 | 동작 |
|---|---|---|
| GET | `/api/v1/listings?page=0&size=20&sort=LATEST` | 비회원 허용 ACTIVE 목록·조합 필터·페이지 |
| GET | `/api/v1/listings/{listingId}/thumbnail` | 비회원 허용 ACTIVE 대표 사진 한 장 |
| GET | `/api/v1/listing-draft-products` | 보유 중인 제품 목록 |
| GET | `/api/v1/listing-drafts?page=0&size=20` | 내가 작성했고 현재 소유 중인 제품의 저장본 목록 |
| GET | `/api/v1/products/{productId}/listing-draft` | 저장본 상세 조회, 없거나 접근할 수 없으면 404 |
| GET | `/api/v1/products/{productId}/listing-draft/composition` | 판매 화면용 제품 정보·사양·사진 |
| GET | `/api/v1/products/{productId}/listing-draft/publication?page=0&size=20` | 현재 소유자 전용 공개 예정 제품 정보·누적 핵심 이력 |
| GET | `/api/v1/products/{productId}/listing-draft/preview?draftId={draftId}&version={version}&page=0&size=20` | 저장본 작성자이자 현재 소유자 전용 읽기 전용 미리보기 |
| GET | `/api/v1/products/{productId}/listing-draft/preview/images/{imageId}?draftId={draftId}&version={version}` | 같은 권한·버전을 확인한 선택 사진만 제공 |
| GET | `/api/v1/products/{productId}/listing-draft/images/{imageId}` | 소유자 전용 제품 사진 |
| POST | `/api/v1/products/{productId}/listing-draft` | 처음 저장 201, 저장본이 이미 있으면 409 |
| PUT | `/api/v1/products/{productId}/listing-draft?draftId={draftId}` | 기존 초안 전체 교체 200, 본문에 조회한 version 필수 |
| DELETE | `/api/v1/products/{productId}/listing-draft?draftId={draftId}&version={version}` | 저장본과 사진 선택 삭제 204 |
| POST | `/api/v1/products/{productId}/listings` | 본문 draftId·version의 초안 게시. 최초 201·같은 요청 재시도 200 |
| GET | `/api/v1/listings/{listingId}?page=0&size=20` | 로그인한 회원용 ACTIVE·RESERVED 상세 |
| GET | `/api/v1/listings/{listingId}/management` | 게시자이자 현재 소유자 전용 편집 정보·사진 선택지 |
| PUT | `/api/v1/listings/{listingId}` | ACTIVE 판매글 전체 수정·내용 버전 검사 |
| POST | `/api/v1/listings/{listingId}/cancel` | 판매 중지·관련 상태 취소·이력 비공개·기록 보존 |
| GET | `/api/v1/listings/{listingId}/images/{imageId}` | 같은 상세 권한으로 선택된 제품 사진만 제공 |

저장 요청은 `title`, `description`, `price`, `conditionGrade`, `selectedImageIds`, `version`을 받는다.
공백 문자열은 null로 정리하고, 사진 선택을 생략하면 빈 배열로 저장한다.
기존 초안을 저장할 때는 직전 응답의 `version`이 필요하며 충돌하면 기존 저장본을 유지하고 409를 반환한다.
수정·삭제는 조회한 `draftId`도 함께 검사한다. 삭제 후 새 저장본의 version이 다시 0이어도 이전 화면이 새 저장본을 덮어쓰거나 삭제할 수 없다.
POST는 생성 전용이고 기존 저장본의 수정은 PUT으로 보낸다. PUT에서 생략한 선택 필드는 null 또는 빈 사진 배열로 교체한다.

목록은 `data.items`와 `data.page(number,size,totalElements,totalPages,hasNext)`를 반환한다.
기본 20개, 최대 100개이며 수정 시각·초안 번호 내림차순으로 정렬한다. 페이지를 자르기 전에 작성자·현재 소유권·제품 보관 상태를 검사한다.

## 화면 흐름

판매글 작성 화면의 내 임시저장 목록에서 이어쓰거나, 보유 제품을 선택하면 접근 가능한 기존 저장본을 불러온다.
제목·가격·설명·등급·사진 순서·대표 선택과 저장 버전을 복원한다. URL에는 선택 제품 번호만 기록해 새로고침 후에도 같은 제품을 다시 연다.
본문과 인증 정보는 브라우저 저장소에 보관하지 않는다.

수정·삭제 충돌 시 작성 중인 내용을 유지하고 저장본 다시 불러오기를 제공한다. 다시 불러오거나 저장하지 않은 내용이 있는 제품을 변경할 때는 확인한다.
삭제는 사용자 확인 후 수행하고, 선택 중이던 저장본을 삭제하면 해당 제품의 빈 작성 화면으로 돌아간다.

현재 입력 제한은 제목 60자, 설명 2,000자, 사진 20장이다. 가격은 1원 이상 12자리 이내의 정수,
상태 등급은 1~5다. 사진 배열의 첫 번째 항목이 대표 사진이다.

## 제품 조회와 저장 구조

- 판매 폼의 제품 기본 정보·사양·사진은 `ProductService`에서 제공하는 값을 사용하며 현재 사양을 별도로 계산하지 않는다.
- 저장 목록은 제품명과 현재 소유권을 한 번에 검사하는 조회를 사용한다. 개수 조회와 제한된 목록 조회로 처리하며 본문·사진 컬렉션을 읽지 않는다.
- 판매용 조회는 `getForListing`을 사용해 시리얼을 조회·복호화하지 않는다. 사진 제공은 제품 서비스의 기존 `image` 기능을 재사용한다.
- 판매 화면의 DTO에는 필요한 필드만 복사한다. 소유자용 제품 응답에 개인정보가 추가되더라도 시리얼·증빙·저장소 키를 그대로 전달하지 않는다.
- 수정은 제품 서비스의 소유권 검사·제품 행 잠금 → 초안 작성자·버전 검사 → 사진 소속 검사 → 내용과 사진 선택 저장 순서로 같은 트랜잭션에서 처리한다.
- `draft_images`에는 `draft_id`, `product_image_id`, `sort_order`, `is_primary`를 저장한다. 사진 중복·순서 중복·복수 대표를 막고 실제 초안·제품 사진을 외래키로 참조한다.
- 초안을 삭제하면 사진 선택 관계도 삭제한다. 제품 화면의 사진 순서·대표 선택과 사진 파일은 변경하지 않는다.
- 제품 사진을 삭제하면 해당 사진의 초안 선택도 정리하고 남은 선택의 순서·대표 사진과 초안 버전을 갱신한다. 이전 화면에서 저장한 버전으로 덮어쓰는 요청은 충돌로 처리한다.
- `V2026102002__align_listing_draft_images.sql`은 기존 `listing_draft_images`의 사진 순서와 대표 선택을 새 구조로 옮긴다. 기존 초안의 내용과 버전은 유지한다.
- 초안의 작성자·버전·PRIVATE 제한은 접근 제어와 저장 충돌 방지를 위해 유지한다.

## R03 공개 예정 정보

[WBS R03-1~3](https://app.notion.com/p/3f23550b7b55802ca75ceaff66e09a52)은 공개 예정 제품 정보·누적 핵심 이력 구성, 이전 소유자·정정·무효 표시와 정렬, 개인정보·증빙 노출 방지를 다룬다.
미리보기 요청 시 작성 내용을 저장하고 게시 화면을 구성하는 작업은 R04다.

- `publication` 조회는 제품 행 잠금 안에서 현재 소유권을 검사하며 저장본 생성·수정·공개 상태 변경을 하지 않는다.
- 제품 정보는 `ProductService.getForListing`에서 가져오고 명시적 허용 필드만 응답한다. 개인 제품 별칭·시리얼·소유자·문서·파일 키는 제외한다.
- 이력 담당 기능은 `ListingHistoryReader`를 구현해 같은 제품의 누적 핵심 이력을 제공한다. 다른 제품·중복·불완전한 행이 섞이면 503으로 전체 응답을 거부한다.
- 원천은 최대 10,000건의 전체 이력을 반환한다. 현재 공개 상태·작성자별로 일부 이력을 걸러내지 않는다. 이 한도를 넘는 제품은 실제 이력 연동 시 DB 조회에서 전체성·페이지 계약을 확장해야 한다.
- 발생일 → 등록 시각 → 이력 번호 내림차순으로 정렬한 뒤 페이지를 나눈다. 기본 20개·최대 100개다. VOID도 목록에 남기고 유효 건수에서는 제외한다.
- 작성자 번호는 이전 소유자 여부 계산에만 사용한다. 시스템 TRANSFER는 당사자 정보 없이 유형·날짜·상태만 표시한다.
- 자유 입력인 제목·설명·업체·교체 부품·정정 사유는 원천의 개인정보 제거·공개 검토가 끝난 경우에만 사용한다. 미검토 내용은 숨기되 이력 자체와 정정·무효 표시는 유지한다.
- 이메일·전화·식별번호·비용·시리얼·증빙 등을 찾는 보조 검사를 거친다. 정규식이 모든 이름·주소를 판별하는 것은 아니며, 원천의 공개 검토를 대신하지 않는다. 감사 로그 JSON이나 증빙·연결 여부는 받지 않는다.
- 이력 구현체가 없으면 `history.status=UNAVAILABLE`을 반환한다. 실제 이력이 없는 경우인 `READY`와 빈 목록을 구분한다. 작성 화면도 연동 준비 중과 이력 없음을 구분해서 표시한다.
- `sale-draft-demo`에서만 샘플 이력을 공급하고 `history.sample=true`와 화면 안내를 표시한다. 일반 프로필에서는 샘플을 제공하지 않는다.

현재 main에는 이력 DB·조회 서비스가 없으므로 실제 누적 이력 연결은 남아 있다. R03 조회 API·표시·정렬·공개 필드 검증을 먼저 구현한 상태이며,
샘플 검증을 실제 이력 연동 완료로 간주하지 않는다. 실제 어댑터는 공개 검토·누적 이력의 완전성·현재 사양 계산과 함께 검증해야 한다.

## R04 게시 화면 미리보기

요구사항 SALE-04와 WBS R04-1~3을 구현한다. 화면의 미리보기 버튼은 현재 입력을 기존 POST/PUT API로 먼저 임시저장하고, 성공 응답의 초안 번호·버전으로 미리보기를 조회한다.

- 저장 실패·버전 충돌 시 미리보기 조회를 보내거나 화면을 열지 않고 입력을 유지한다. 저장은 성공했지만 미리보기 조회가 실패하면 저장 완료 사실과 오류를 함께 안내한다.
- GET은 초안을 생성하지 않는다. 초안 작성자이면서 현재 소유자인지 제품 행 잠금 안에서 검사한다. 다른 사용자의 초안·소유권 이전된 초안은 404이며, 수정·삭제 후 재생성된 초안 번호나 버전이 다르면 409다.
- 저장된 제목·설명·가격·등급, 선택 사진의 순서·대표 사진, R03의 공개 허용 제품 정보와 누적 이력을 반환한다. 초안 ID·버전·저장 시각은 판매자용 미리보기 메타데이터다.
- 사진 경로로 직접 접근해도 같은 권한·버전과 해당 초안의 사진 선택을 확인한다. 증빙·파일 저장 경로·작성자 계정은 제공하지 않으며 JSON·사진 모두 `no-store`를 적용한다.
- 빈 제목·가격·등급·설명이나 사진 없음은 작성 중 상태로 표시한다. 게시 필수값 검사는 R05에서 처리한다.
- `listing-detail.js`의 읽기 전용 렌더러를 사용하며 향후 실제 판매 상세에서도 재사용할 수 있다. 기존 정적 판매 상세 시안의 샘플 판매자·가격·AI 요약·증빙 표시를 가져오지 않는다.
- 모든 입력 텍스트를 `textContent`로 출력한다. 이전 소유자·정정·무효 표시, 이력 페이지 구분과 연동 준비 중 안내는 R03 정책을 그대로 사용한다. 개별 이력을 제외하는 기능은 없다.
- 미리보기를 닫아도 입력과 사진 선택은 유지되며, 초안은 비공개로 남는다. 미리보기 조회·사진 조회로 판매글을 생성하거나 이력 공개 상태를 변경하지 않는다.

실제 이력 공급자와 이력 기반 현재 사양 계산의 연동은 여전히 남아 있다. 현재 샘플은 미리보기 동작 검증용이며 실제 이력 연동 완료를 뜻하지 않는다.

## R05 최종 게시

요구사항 SALE-02·07, ERD listings·listing_images와 WBS R05-1~3을 기준으로 구현한다.

- `V2026102101__create_published_listings.sql`로 게시된 판매 조건·상태·사진 선택을 생성한다. 기존 초안과 제품 사진 데이터는 보존한다.
- 게시 확인 → 현재 입력 임시저장 → 저장 응답의 초안 ID·버전으로 게시 요청 → 실제 판매글 상세 진입 순서다. 제목·가격(1원 이상 정수)·1~5등급·설명·대표 사진이 필수다.
- 서버는 제품 행 잠금 안에서 현재 소유자·초안 작성자·초안 ID·버전·사진 소속 및 존재를 검사한다. 진행 중 거래·이전 요청과 ACTIVE/RESERVED 판매글이 있으면 게시를 거부한다.
- 판매글·사진 생성, 이력 공개, 사용한 초안·사진 선택 삭제, LISTING_PUBLISHED 감사 기록을 하나의 트랜잭션으로 처리한다. 이력 공개 이후 또는 초안 삭제 이후에 오류가 발생해도 모두 롤백한다. 다른 제품의 초안은 삭제하지 않는다.
- `active_slot`은 ACTIVE/RESERVED에서 1, 종료 상태에서 NULL이어야 한다. CHECK와 `(product_id, active_slot)` UNIQUE를 함께 사용해 PostgreSQL·H2에서 열린 판매글 하나를 보장한다.
- 삭제된 초안과 연결하는 `source_draft_id`·`source_draft_version`은 FK가 없는 게시 재시도 식별자다. 동일 요청은 200과 기존 판매글 번호를 반환하고 이력 공개·감사 기록을 반복하지 않는다. 종료된 글을 재게시하거나 다른 초안을 덮어쓰지 않는다.
- 응답이 유실되면 화면은 같은 초안 ID·버전으로 결과를 다시 확인할 수 있다. 불확실한 동안 입력을 잠가 다른 내용으로 재시도하지 않는다.
- 회원용 상세·선택 사진은 ACTIVE/RESERVED이면서 판매자가 현재 소유자인 경우만 제공한다. 비회원은 401, 종료·접근 불가 글은 404다. 초안·판매자 계정·시리얼·증빙·파일 경로는 공개 DTO에 없다.
- 공통 읽기 전용 상세 화면을 재사용하고 정적 판매자·가격·AI 샘플을 실제 상세에서 제거했다. 목록·필터는 아래 R06, 판매글 관리는 R07을 따른다.
- 채팅의 임시 초안 조회를 실제 listings 조회로 변경했다. 판매 중/예약/종료 상태와 게시 당시 판매자를 그대로 전달한다. 게시에 사용한 제품 사진은 ACTIVE/RESERVED 판매글에서 제외하기 전까지 제품 관리에서 삭제할 수 없다.
- `V2026102102` Java 마이그레이션은 기존 채팅 참조·초안·판매글의 최대 번호보다 큰 값에서 새 판매글 번호를 시작한다. 기존 초안 기반 채팅 번호가 다른 새 판매글에 연결되지 않게 하며, 기존 방·메시지는 삭제하거나 임의로 재연결하지 않는다.
  초안을 판매글로 읽는 구버전과 새 버전을 동시에 운영하지 않는 전환 배포를 전제로 한다.

### 실제 연동과 로컬 검증의 구분

현재 거래·소유권 이전·이력 공개 도메인의 구현체가 없으므로 다음 두 계약은 운영 연결이 남아 있다.

- `ListingPublishConstraints.inspect(productId)`: 현재 트랜잭션의 제품 잠금 안에서 거래 진행 여부와 이전 요청 진행 여부를 모두 확인한다. 정보가 없으면 ready=false를 반환한다.
- `ListingHistoryPublisher.publish(productId, listingId, sellerId)`: 같은 DB·현재 트랜잭션에서 이전 소유자의 기록까지 포함한 누적 이력 공개를 처리한다. 별도 트랜잭션·비동기·외부 HTTP로 분리하지 않으며 실패 시 예외로 게시도 롤백한다. 이력 추가·정정도 같은 제품 잠금을 사용해야 한다.

구현체가 없거나 준비되지 않았으면 **일반 프로필에서는 503 SALE_004로 게시를 차단하고 초안을 유지한다.** 이력 조회가 UNAVAILABLE인 경우도 빈 이력으로 게시하지 않는다.
`sale-draft-demo`에서만 별도 샘플 DB의 거래·이전 없음과 모형 product_events의 공개 상태 변경을 제공한다. 화면에는 샘플 이력 안내가 유지된다. 이는 실제 도메인 연동 완료를 뜻하지 않는다.
새 데모 마이그레이션 `V2026102100`은 기존 빈 판매글 모형을 legacy_demo_listings로 보존하고 실제 테이블 생성 순서를 맞춘다. 운영 마이그레이션을 수정하거나 모형 테이블을 운영에 생성하지 않는다.

## R06 공개 목록·조건 검색·회원 상세 진입

SALE-05, MVP 조회 범위와 NFR의 페이지·조회 수 제한에 따라 구현한다. 기존 `listings`, `products`, `laptop_details`, `listing_images`, `product_images`를 읽으며 새 마이그레이션은 없다.

- 목록은 ACTIVE이면서 게시 당시 판매자가 현재 제품 소유자인 글만 제공한다. 보관된 제품·예약·완료·중지 글은 개수 조회와 페이지 조회 모두에서 먼저 제외한다. RESERVED 상세는 기존과 같이 로그인한 회원에게 유지한다.
- 카드 DTO에는 판매글 번호·제목·가격·상태 등급·게시 시각·제조사·모델·필터용 사양·대표 사진 URL만 포함한다. 본문·누적 이력·제품 별칭·작성자 계정·초안·시리얼·증빙·저장소 키를 포함하지 않는다. 목록 조회는 이력 공급자를 호출하지 않는다.
- 기본 page=0·size=20, size 최대 100. `sort=LATEST|PRICE_ASC|PRICE_DESC`만 허용하고 동일 시각·가격은 판매글 번호 내림차순으로 정렬한다. 정렬 SQL은 enum의 고정 구문만 사용한다.
- 조건은 `manufacturer`, `minPrice`, `maxPrice`, `cpu`, `gpu`, `minRamGb`, `minStorageGb`, `storageType`, `os`, `minConditionGrade`이며 입력한 모든 조건을 AND로 조합한다. 가격 경계는 포함하고 0 이상 12자리 정수이며 최소값이 최대값보다 크면 400이다. 용량은 양의 정수, 최소 등급은 1~5, 저장장치 종류는 SSD/HDD/MIXED다.
- 제조사는 제품 기능과 같은 대소문자·공백·하이픈 정규화 후 일치 비교한다. CPU·GPU·OS는 대소문자 구분 없이 포함 검색하며 `%`, `_`, `!`는 검색 와일드카드가 아닌 입력 문자로 취급한다. 값은 SQL 바인딩 파라미터로 전달한다. 사양이 없는 제품은 해당 사양 조건이 있을 때 제외한다.
- 대표 사진은 공개 전용 `/thumbnail` 경로로 한 장만 제공한다. 매 요청마다 ACTIVE·현재 소유권·제품 보관 상태·선택 사진·파일 접근을 재확인한다. 예약·종료·소유권 변경 후 기존 대표 사진 URL도 404가 된다. 다른 제품의 사진이나 삭제된 사진은 대표 사진 URL로 제공하지 않는다. 상세 사진 경로는 계속 회원 전용이다.
- JSON과 사진은 `no-store`, 사진은 `nosniff`를 사용한다. 공개 GET은 만료된 access_token 쿠키가 있어도 비회원으로 사용할 수 있으며, 명시적인 Authorization 헤더의 검증과 비공개 경로의 인증은 유지한다.
- 중고거래 목록의 고정 카드·가짜 개수·판매자·찜·이력/증빙 표시를 실제 목록으로 교체한다. 조합 필터·정렬·페이지·초기화·빈 결과·오류 재시도·모바일 필터를 제공하며 `/?market=1`의 URL 조건을 새로고침 후 복원한다. 입력 텍스트는 `textContent`로 표시한다.
- 카드는 실제 listingId의 상세 화면으로 이동한다. 비회원 상세 요청이 401이면 데이터 대신 로그인 안내를 표시하고, 로그인 성공 후 원래 상세로 복귀한다. 작성·게시와 같은 API를 사용하므로 게시 후 목록에 반영된다. 랜딩 등 다른 정적 시안 전체를 연결한 것은 아니다.

현재 사양 검색은 제품 기능이 제공하는 `laptop_details` 값 기준이다. 이력 기반 사양 계산·실제 누적 이력·거래/이전 연동과 상세 AI 요약은 각각 해당 후속 기능의 연결이 필요하다. 공개 목록·대표 사진은 이력 연동이 없어도 동작하며, 상세·게시의 기존 이력 준비 상태 검사는 완화하지 않는다.

## R07 판매글 수정·판매 중지

SALE-06·07, HIST-05, TX-05와 ERD listings의 상태·기록 보존 규칙을 따른다. 게시글의 물리 삭제는 제공하지 않는다. 사용자가 판매글을 내리는 행위는 CANCELLED 전환이며, 판매글·선택 사진·채팅·제품·누적 이력 기록을 보존한다. 종료된 글은 재공개하지 않고 새 글로 재판매한다.

- 관리 조회·수정·중지는 게시 당시 판매자이면서 현재 제품 소유자인 회원만 가능하다. 다른 회원, 이전 소유자, 새 소유자와 보관된 제품은 404다. 관리 정보는 공개 목록에 섞지 않는다. 회원 상세의 `canManage`는 현재 요청자에게 관리 버튼을 보여줄지 판단하는 값이며, 실제 권한은 관리 API에서 다시 확인한다.
- PUT은 `version`, `title`, `description`, `price`, `conditionGrade`, `selectedImageIds` 전체가 필수다. 제목 60자·설명 2,000자·1원 이상 12자리 정수·1~5등급·사진 1~20장을 검증한다. 사진 중복·다른 제품·삭제·파일 유실을 거부하고 첫 선택을 대표 사진으로 저장한다.
- 수정 시 제품 → 판매글 행 순서로 잠그고 내용 버전을 확인한다. ACTIVE만 수정 가능하며 RESERVED·SOLD·CANCELLED는 409다. 내용 버전은 저장 시 1 증가하고 제품 정보·사양·이력·게시자·게시 시각은 바꾸지 않는다. 이전 버전의 수정·중지 요청은 409다.
- 중지 요청은 `{"version":0,"reason":"판매 중지 사유"}` 형식이며 사유는 1~500자다. ACTIVE·RESERVED를 CANCELLED로 전환하고 `active_slot`을 해제한다. 내용 버전 자체는 상태 변경만으로 증가시키지 않는다. 같은 버전으로 중지를 재시도하면 부작용과 감사 기록을 반복하지 않으며, 새 재판매 글의 공개 이력을 숨기지 않는다.
- 중지 시 글의 상태 변경, PENDING 구매 요청 정리, 예약 거래·내부 이전 취소 및 링크·QR 무효화, 열린 판매글이 없는 제품의 이력 PRIVATE 전환, 수행자·사유·시각의 감사 기록을 한 트랜잭션으로 처리한다. 중간 실패는 전부 롤백한다. 기존 채팅 참여자의 대화 기록은 삭제하지 않는다.
- `ListingTradeCanceller`와 `ListingHistoryPrivatizer`는 외부 도메인이 구현할 같은 DB·같은 트랜잭션 계약이다. 두 구현체가 없거나 연동 불가를 보고하면 503이다. 처리 중 발생한 오류도 전체 롤백하며 중지를 성공으로 응답하지 않는다. 거래 쪽 예약/취소/이전 구현도 제품 → 판매글 → 구매 요청/이전의 잠금 순서를 지켜야 한다. pending 거래 DDL을 임의로 운영 Migration에 편입하지 않았다.
- 수정·중지는 기존 audit_logs의 전후 판매 조건·사진 선택·상태·버전에 기록한다. 사유는 내부 감사 데이터이며 공개 DTO에 포함하지 않는다. 새 스키마·의존성은 없다. AI 최신화는 후속 R09에서 `content_version`을 비교해야 한다.
- 실제 상세의 소유자용 `내 판매글 관리`에서 제목·가격·등급·설명·사진 순서/대표 사진을 수정한다. 저장하면 실제 상세·목록·대표 사진에 반영된다. 중지는 사유 입력·확인 창을 거쳐 처리하며, 충돌 시 입력을 보존하고 명시적으로 최신 내용을 다시 불러오게 한다. 판매 중지 성공 후에는 목록으로 돌아갈 수 있다.

현재 일반 실행에는 거래·이전 취소와 이력 비공개 운영 어댑터가 없어 판매 중지는 503으로 차단된다. ACTIVE 수정은 해당 어댑터 없이 동작한다. `sale-draft-demo`는 거래·이전 데이터가 없는 샘플 ACTIVE 중지와 샘플 product_events의 PRIVATE 전환만 제공하고 RESERVED 중지는 거부한다. 테스트의 RESERVED 취소 모형은 실제 거래·이전 모듈 연동 완료를 뜻하지 않는다.

## 연동 범위

제품의 DB 이름 변경과 이력을 반영한 현재 사양 계산은 제품·이력 기능에서 처리한다.
현재 main의 제품 조회는 아직 `laptop_details`를 읽는다. SALE이 제품 서비스를 사용하도록 연결한 것과,
제품 서비스가 최신 ERD의 계산 규칙까지 구현한 것은 구분해야 한다.

인증은 공통 보안 설정을 따른다. 프런트는 `PastportApi.fetch`를 통해 인증 쿠키와 쓰기 요청의 CSRF 헤더를 전송한다.
CSRF는 공통 인증 모듈에서 `XSRF-TOKEN` 쿠키를 읽어 `X-XSRF-TOKEN` 헤더로 전달하며, 인증 토큰을 판매 화면에서 직접 읽거나 저장하지 않는다.
파일 저장은 기존 `FileStorage`를 사용한다.

소유권 이전에 따른 실제 초안 정리는 후속 구현 범위다. 이전 완료 후 남아 있는 초안은 이전 소유자·새 소유자 모두 조회·수정·삭제·미리보기할 수 없다.
실제 게시의 외부 도메인 연동은 위 R05 계약을 따르며, AI는 호출하지 않는다.

## 검증과 로컬 확인

`ListingDraftHttpTest`는 운영 마이그레이션으로 생성한 테이블에서 실제 HTTP·JWT·제품 서비스·JPA 저장을 검증한다.
제품 등록·사진 업로드 후 초안 작성, 소유권과 사진 검사, 사진 순서·대표 선택, 버전 충돌과 동시 저장을 포함한다.
R02는 저장본 재조회·페이지 구분·권한 필터·수정·삭제와 재생성 후 이전 화면의 요청 거부, 동시 수정·삭제도 검증한다.
R03는 실제 HTTP에서 제품 공개 허용 필드·조회 권한·페이지·정렬·이전 소유자·정정·무효 표시와 미검토 내용 제외를 검증한다. 이력 공급자는 테스트 전용 대역이며 제품은 운영 마이그레이션 DB를 사용한다.
R04는 저장된 내용·사진 순서, 불완전 초안, 작성자·소유자 권한, 버전 충돌·삭제 후 재생성, 선택 사진의 직접 접근, 이력 표시와 조회 실패 후 초안 보존을 검증한다. 화면에서는 저장 후 미리보기 열기·복귀·입력 보존·잘못된 가격과 충돌 시 차단을 확인한다.
R05는 필수값·권한·거래/이전 제약·이력 준비 상태, 같은 요청 재시도·동시 게시·DB 고유 제약, 공개 도중/초안 삭제 후 실패의 전체 롤백, 회원 상세·사진 접근과 종료 상태 차단, 게시 사진 삭제 보호, 채팅의 실제 판매글 연결을 검증한다. 이력 공개는 테스트 전용 DB 모형을 사용한다.
`ListingBrowseHttpTest`는 일반 보안 설정에서 비회원 목록·대표 사진과 회원 상세의 경계를 검증한다. ACTIVE·현재 소유권·보관 여부의 페이지 전 필터, 조건 AND 조합·정렬·페이지·입력 검증·SQL/와일드카드 입력, 공개 필드 제한, 만료 쿠키, 사진 삭제·다른 제품 사진·상태 변경 후 URL 차단을 실제 HTTP·운영 마이그레이션 DB로 검사한다. 같은 `SALE_DRAFT_TEST_DB_*`로 PostgreSQL에서도 실행한다.
`ListingManagementHttpTest`는 일반 보안 설정에서 관리 권한, 필수 입력·사진 검사, 상태·내용 버전, 공개 조회 반영, 쿠키 CSRF, 동시 수정과 중지 경합을 검증한다. 외부 거래·이전·이력 효과는 테스트 전용 DB 모형을 사용하며 전체 롤백·예약 취소·중복 요청·재판매 후 이전 취소 재시도의 영향을 확인한다. `ListingManagementServiceTest`는 필수 어댑터 누락 시 중지 이전에 503으로 거부함을 검증한다.
`ListingDraftMigrationTest`는 기존 데이터가 있는 DB의 업그레이드 시 초안 내용·버전·사진 선택 보존을 확인한다.
`SALE_DRAFT_TEST_DB_URL/USER/PASSWORD` 환경 변수를 지정하면 관련 통합 테스트를 전용 PostgreSQL 테스트 DB에서도 실행한다.

```powershell
./gradlew.bat spotlessCheck test build
```

로컬 화면 확인은 `scripts/run-sale-draft-demo.ps1`을 사용한다.
`local,sale-draft-demo` 프로필은 로컬 샘플 전용이며 배포 환경에서 사용하지 않는다.
