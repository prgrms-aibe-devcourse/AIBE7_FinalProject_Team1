# 상품 등록 API와 시리얼 번호 보호

> `TROUBLESHOOTING.md`에 있던 설계 설명을 옮겼습니다. 트러블이 아니라 설계 기록입니다.

### 문제와 목표

노트북 시리얼 번호로 중복 등록을 확인해야 하지만, 번호를 DB에 평문으로 저장하면 DB가 노출됐을 때 번호도 그대로 드러납니다. 또한 나중에 번호 확인이 필요할 수 있어 복원 가능성도 고려했습니다. 상품 등록 시 시리얼 번호를 **중복 확인용 HMAC 지문**과 **복원 가능한 AES 암호문**으로 나눠 저장합니다.

### 상품 등록 흐름

1. 로그인한 사용자가 `POST /api/v1/products`에 상품 정보와 시리얼 번호를 보냅니다.
2. 서버는 JWT에서 사용자 ID를 읽어 제품 소유자로 지정합니다.
3. 시리얼 번호의 공백을 제거하고 대문자로 변환합니다. 예를 들어 `ab12 cd34`와 `AB12CD34`는 같은 번호로 취급합니다.
4. 정규화된 번호로 HMAC 지문을 만들어 기존 제품과 중복되는지 확인합니다.
5. 중복이 아니면 AES-GCM 암호문을 만들고 지문과 암호문을 상품 정보와 함께 저장합니다.
6. 등록 결과에는 시리얼 번호를 포함하지 않습니다.

동시 요청이 사전 중복 검사를 모두 통과하는 경우에도 DB 유니크 제약으로 중복을 방지합니다.

### HMAC 지문: 중복 확인

HMAC은 비밀 키와 데이터를 이용해 고정 길이의 값을 만드는 방식입니다. 이 프로젝트에서는 `HMAC-SHA256`을 사용합니다. 같은 키와 같은 정규화 번호로는 같은 지문이 만들어지므로, DB에 원문 없이도 중복을 확인할 수 있습니다. 지문은 복호화해 원래 번호를 얻는 용도가 아닙니다.

일반 해시도 비교에 사용할 수 있지만, 형식을 추측할 수 있는 번호는 후보 값을 계산해 대조하는 공격을 고려해야 합니다. HMAC은 별도의 비밀 키가 있어야 후보 지문을 계산할 수 있습니다. 키가 함께 유출되면 이 보호 효과도 약해집니다.

### AES-GCM 암호문: 필요 시 복원

AES는 비밀 키를 이용해 암호화하고 복호화하는 대칭키 암호화 방식입니다. 이 프로젝트의 `AES-256-GCM`은 암호화와 함께 암호문 변조 여부도 검증합니다. HMAC 지문으로는 번호를 복원할 수 없으므로 별도의 암호문을 저장합니다.

암호화할 때마다 임의의 IV를 새로 생성하므로 같은 번호의 암호문도 매번 달라집니다. 두 용도의 키는 마스터 비밀값에서 서로 구분해 만듭니다. 현재 복호화 메서드는 구현돼 있지만 확인한 상품 등록·조회 흐름에서는 번호를 복호화해 응답하지 않습니다.

### 대안과 선택의 의미

| 방법 | 장점 | 고려할 점 |
| --- | --- | --- |
| 평문 저장 | 구현과 검색이 간단함 | DB 노출 시 번호가 그대로 드러남 |
| 일반 해시만 저장 | 원문 없이 중복 비교 가능 | 복원 불가; 추측 가능한 번호의 후보 대조 공격 고려 필요 |
| HMAC만 저장 | 비밀 키 없이 후보 지문 계산이 어려움 | 원래 번호 복원 불가; 복원이 필요 없다면 단순한 대안 |
| 암호화만 저장 | 키가 있으면 원래 번호 복원 가능 | 임의 IV를 쓰면 같은 번호도 암호문이 달라 단순 일치 검색이 어려움 |
| HMAC + AES-GCM | 중복 확인과 복원 가능성을 함께 제공 | 두 값과 키의 관리 및 키 교체 계획 필요 |

코드와 커밋에서 확인되는 설계 목적은 평문 저장을 피하면서 중복 검사와 복원 가능성을 함께 확보하는 것입니다. 다른 방법을 검토한 실제 의사결정 과정은 Git 이력만으로 확인할 수 없습니다.

### AWS KMS와 PASETO

- **AWS KMS:** 암호화 키를 관리하는 서비스입니다. AES를 대체하기보다 데이터 키를 보호하는 데 함께 사용할 수 있습니다. 예를 들어 데이터 키로 번호를 암호화하고 KMS 키로 데이터 키를 보호하는 봉투 암호화가 가능합니다. 현재 확인된 구현은 KMS가 아닌 애플리케이션에 제공된 비밀값을 사용합니다. [AWS KMS 암호화 설명](https://docs.aws.amazon.com/kms/latest/developerguide/kms-cryptography.html)
- **PASETO:** 인증 정보를 담는 토큰 형식으로 JWT와 비교할 수 있습니다. 시리얼 번호의 DB 저장 방식인 HMAC과 AES를 직접 대체하지는 않습니다.

### 운영 시 확인 사항

비밀값을 잃으면 기존 암호문을 복호화할 수 없습니다. 비밀값을 변경하면 HMAC 지문도 달라져 중복 확인에 영향을 주므로, 키 백업·접근 통제와 함께 키 교체 시 기존 데이터의 재처리 계획이 필요합니다.
