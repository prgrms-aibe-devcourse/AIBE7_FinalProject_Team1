# R08 AI 판매글 제목·본문 제안

[WBS](https://app.notion.com/p/3f23550b7b55802ca75ceaff66e09a52)의 R08-1~3과 요구사항 AI-01·AI-02·AI-08을 구현한다.
R09 공개 상태 요약·R10 요약 재생성·R11~12 Q&A는 포함하지 않는다.

## API와 호출 흐름

`POST /api/v1/products/{productId}/listing-draft/ai-suggestion`

- 인증된 현재 소유자만 호출한다. 보관 제품·다른 사람 제품·존재하지 않는 제품은 404다.
- 본문을 받지 않는다. 사용자 프롬프트·사용자 번호·선택 이력·문서·채팅을 외부 AI로 전달할 수 없다.
- 현재 소유권·공개 허용 제품 정보와 전체 누적 핵심 이력을 짧은 DB 트랜잭션에서 조회한다.
- 회원별 동시 요청·분당 횟수와 서버 전체 분당 횟수를 Redis Lua로 함께 검사한다.
- DB 트랜잭션과 제품 잠금을 해제한 뒤 Gemini에 요청한다.
- 응답의 형식·길이·민감정보·명백한 금지 표현과 입력에 없는 수치를 검사한다.
- 날짜의 한글·0 없는 월일·점/슬래시 표기는 실제 구매일·보증 만료일·이력 발생일 전체와 대조한 뒤 ISO 형식으로 맞춘다. 날짜 밖의 숫자 비교는 완화하지 않는다.
- 제품 소유권·보관 상태와 자료를 다시 조회하고, 생성 전후 자료가 다르면 결과를 반환하지 않는다.
- 성공 응답은 `ApiResponse.data`에 `productId`, `factsVersion`, `sourceVersion`, `title`, `description`, `generatedAt`, `sample`을 담고 `Cache-Control: no-store`를 사용한다.

제안 생성은 초안·판매글·사진·공개 상태를 저장하거나 변경하지 않는다. 새 DB 테이블·마이그레이션·의존성도 추가하지 않는다.

## 자료 범위

- 기존 `ListingPublicationService`의 공개 허용 투영을 재사용한다. AI용 내부 조회는 화면의 첫 20개·100개가 아닌 전체 이력을 읽는다.
- 이전 소유자의 기록과 정정·무효 기록도 유형·발생일·상태와 함께 포함한다.
- 무효·미검토 기록의 자유 입력은 보내지 않는다. 무효는 사실·횟수에 포함하지 말도록 지시한다.
- 사적인 제품 별칭, 시리얼·저장소 키·증빙·비용·계정·이전 당사자·채팅은 보내지 않는다. 사진도 보내지 않는다.
- 제품 모델명 등 허용 필드에 민감한 문자열이 섞여 있으면 외부 전송 전에 거부한다.
- 원천의 개인정보 검토 계약은 그대로 필요하다. 정규식만으로 모든 이름·주소·민감정보나 생성문 의미를 판별할 수는 없다.
- 전체 입력은 UTF-8 48KB까지다. 한도를 초과하면 일부 이력을 조용히 생략하지 않고 422를 반환한다.
- 실제 이력 구현체가 없으면 이력이 없는 제품으로 가정하지 않고 503을 반환한다. 일반 환경의 조회 연결·활성화 조건은 [실제 이력 조회 연결](LISTING_HISTORY_INTEGRATION.md)을 따른다.

`sourceVersion`은 공개 허용 입력과 제품 `factsVersion`의 SHA-256이다. 원천이 버전 증가를 놓친 경우에도 공개 자료가 바뀌면 검출한다. 외부 이력 구현체는 제품 잠금과 같은 DB·트랜잭션 경계를 지켜야 한다.

## Gemini 연결·설정

기본 모델은 사용자가 지정한 `gemini-3.5-flash-lite`다.
공식 [모델 문서](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite),
[GenerateContent API](https://ai.google.dev/api/generate-content),
[구조화 출력 문서](https://ai.google.dev/gemini-api/docs/generate-content/structured-output)를 기준으로 한다.

서버 환경 변수 또는 Git에서 제외된 `.env`에 설정한다. 사용자 `.env.example` 변경사항은 수정하지 않았다.

```dotenv
GEMINI_API_KEY=실제_키를_로컬에서_입력
AI_MODEL=gemini-3.5-flash-lite
AI_LISTING_ENABLED=true
AI_TIMEOUT_SECONDS=20
AI_USER_REQUESTS_PER_MINUTE=3
AI_GLOBAL_REQUESTS_PER_MINUTE=30
```

`GEMINI_API_KEY`가 없으면 기존 `AI_API_KEY`를 사용한다. 빈 키·예제 키로는 외부 호출하지 않는다.
기존의 Redis 연결 설정도 필요하다. 로컬에서는 `docker compose up -d postgres redis` 후 일반 서버를 실행한다.

- Gemini 키는 URL 쿼리나 브라우저에 넣지 않고 서버의 `x-goog-api-key` 헤더로만 보낸다.
- 운영 목적지는 고정된 Google HTTPS 주소다. 사용자 입력이나 설정으로 임의 URL을 지정할 수 없다.
- `generationConfig.responseFormat.text.schema`로 제목·본문만 받는다. 후보 1개·출력 최대 2048토큰이다.
- 도구·검색·파일·대화 상태를 사용하지 않고 입력 자료를 지시문과 분리한다. 모든 원천 자유 입력을 신뢰할 수 없는 데이터로 취급한다.
- 연결 대기 최대 5초, 응답 전체 기본 20초(설정 가능 1~60초), 수신 본문 최대 64KB다.
- 불완전 종료·안전 차단·형식 오류·추가 필드·중복 JSON 키·도구 호출 응답은 거부한다.
- 자동 재시도하지 않는다. 재시도는 사용자가 누르며 새 횟수로 계산한다. 외부에 전송한 뒤 실패한 요청도 횟수에서 차감한다.
- 기본 제한은 회원별 동시 1개·분당 3회, 서버 전체 분당 30회다. 카운터·잠금은 모든 서버가 공유하는 Redis에서 원자적으로 처리한다.
- Redis 장애 시 무제한 요청으로 바꾸지 않는다. 동시 요청 잠금은 응답 기한 +15초 뒤 만료되며, 해제할 때 요청별 토큰을 비교한다.
- API 키·원천·공급자 오류 본문·AI 결과 원문은 로그나 오류 응답에 포함하지 않는다. 공급자 측 데이터 처리 정책은 팀의 서비스 설정에 따른다.

## 작성 화면

제품 선택 → AI 제안 생성 → 별도 제안 영역에서 확인 → 제목·설명에 적용 → 직접 편집 → 명시적 임시저장 → 미리보기 → 최종 게시 순서다.

- 생성 중에도 직접 입력할 수 있다. 결과가 도착해도 작성하던 내용을 자동으로 덮어쓰지 않는다.
- 적용할 때 기존 제목·설명이 있으면 교체 확인을 받는다. 가격·등급·사진은 그대로 둔다.
- 적용은 화면만 바꾸고 기존 변경 감지에 반영한다. 저장은 기존 POST/PUT 초안 API로 따로 실행한다.
- 실패·시간 초과·요청 제한 안내와 재시도를 제공한다. 429는 `Retry-After` 동안 생성 버튼을 잠그고 직접 작성은 허용한다.
- 제품 변경·화면 이탈·직접 작성 선택은 요청을 취소하고 이전 제품의 늦은 결과를 버린다.
- AI 결과는 `textContent`로만 표시하며 브라우저 저장소에 보관하지 않는다.
- 생성 시점의 자료를 검증한다. 이후 사용자가 편집·적용한 초안은 작성자 입력이므로 최신 제품 사실과의 의미 일치까지 자동 보장하지 않는다. 판매자는 내용을 확인·수정해야 한다.

## 날짜 표기에 따른 간헐적 첫 요청 실패 보완

2026-11-01 실제 Gemini와 합성 공개 제품을 이용한 연속 검사 3회 중 3번째 응답에서 HTTP 200·STOP·정상 길이의 제안이 AI_003으로 거부됐다. 원천의 2025-05-20·2025-04-02를 각각 2025년 5월 20일·2025년 4월 2일로 출력했고, 기존 숫자 비교가 05/04와 5/4를 다른 값으로 판단했다. 항상 첫 요청에만 발생하는 초기화 문제가 아니라 생성된 날짜 표기에 따른 간헐적 검증 실패였다. 사용자의 과거 실패 응답 원문은 보관하지 않아, 실제 모델에서 재현한 같은 오류와 구분한다.

ListingSuggestionService는 생성 결과를 AiListingTextPolicy.validateSuggestion으로 전달한다. 이 경로에서 제목·본문의 날짜를 원천 JSON의 product.purchaseDate, product.warrantyExpiresAt, history.occurredOn과 대조한 뒤 ISO 형식으로 정리하고 기존 검증을 적용한다. 자유입력 본문에 쓴 날짜를 새 근거로 인정하지 않으며, 등록되지 않은 날짜 조합·달력에 없는 날짜·새 메모리 숫자는 거부한다. 05를 일반 숫자 5로 풀어서 5GB까지 허용하지 않는다. 요청당 외부 생성은 한 번이며 자동 재시도는 추가하지 않는다.

기존 HTTP 서비스에 한글 날짜 응답과 ISO 날짜 응답을 차례로 주면 첫 요청 502·다음 요청 200인 실패를 수정 전 재현했다. 회귀 검사는 한글 날짜도 첫 요청 200이고 외부 생성 호출이 1회이며 초안·판매글이 저장되지 않는지 확인한다. ListingSuggestionLiveTest는 AI_SUGGESTION_LIVE=true와 로컬 AI_LIVE_API_KEY를 명시한 경우에만 실제 Gemini를 3회 호출하며, 운영 DB·계정을 사용하지 않고 합성 자료 결과만 build/reports/ai-suggestion-live에 보관한다. 키·원문을 실행 인자나 서버 로그에 넣지 않는다.

실호출을 명시적으로 실행할 때는 위 환경변수를 설정한 별도 프로세스에서 `./gradlew test --tests org.example.springtestci.ai.service.ListingSuggestionLiveTest --rerun-tasks`로 실행한다. 환경변수만 변경하면 이전 테스트 결과가 재사용될 수 있으므로 재실행 옵션이 필요하다. 일반 회귀 검사에서는 `AI_SUGGESTION_LIVE`를 설정하지 않는다.

## 오류

| HTTP | 코드 | 의미 |
|---|---|---|
| 503 | AI_001 | 키·공급자·Redis 연결을 사용할 수 없음 |
| 504 | AI_002 | 외부 AI 응답 기한 초과 |
| 502 | AI_003 | AI 출력 형식·길이·정책 검사 실패 |
| 503 | AI_004 | 전체 이력 원천 또는 안전한 입력 준비 안 됨 |
| 409 | AI_005 | 생성 중 제품 사실·공개 자료 변경 |
| 422 | AI_006 | 전체 자료가 입력 한도 초과 |
| 429 | AI_007 | 동시 요청·횟수 제한 또는 공급자 제한, Retry-After 포함 |

모든 오류에서 직접 작성·기존 초안 저장은 계속 이용할 수 있다.

## 검증

- `ListingSuggestionHttpTest`: 일반 보안·실제 JWT/CSRF·운영 마이그레이션 DB에서 권한, 비저장, 전후 버전, 잠금 해제, 전체 이력·민감정보 제외, 공급자 장애·요청 제한을 검증한다. 외부 AI와 이력은 테스트 대역이다.
- `GeminiListingSuggestionGatewayTest`: 로컬 HTTP 서버로 요청 모델·스키마·키 전달 위치, 공급자 오류·429·시간 초과·잘못된 출력·본문 한도를 검증한다. 실제 외부 API 호출은 하지 않는다.
- `AiListingTextPolicyTest`: 길이·민감정보·금지 표현·입력에 없는 수치를 검사한다. 이 검사는 생성문 전체 의미의 정확성을 증명하지 않는다.
- `AiSuggestionRateLimiterTest`: Redis 장애·거부·잠금 해제 실패를 검사한다.
- `AiSuggestionRedisTest`: `AI_TEST_REDIS_PORT`가 지정된 테스트 Redis에서 실제 Lua 동시성·회원/전체 제한·TTL·이전 토큰 해제를 검증한다. 격리된 임의 테스트 접두사만 사용한다.
- `SALE_DRAFT_TEST_DB_URL/USER/PASSWORD`를 지정하면 HTTP 검증을 전용 PostgreSQL `sale_ai_test` DB에서도 실행한다.

실제 Gemini 키·계정의 모델 접근성과 운영 이력 구현체를 연결한 실호출은 별도 확인이 필요하다. 샘플·테스트 대역 검증을 운영 연동 완료로 간주하지 않는다.
