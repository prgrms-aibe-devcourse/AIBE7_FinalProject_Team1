# 제품 AI 실제 모델 품질 확인

제품 이력 Q&A와 판매글 카드 요약을 실제 Gemini로 확인하는 선택 실행 검사다. 평소 테스트와 CI에서는 외부 모델을 호출하지 않는다. 가격·품질·구매 추천을 평가하는 기능이 아니라, 등록된 제품 기록을 정확히 설명하는지 확인한다.

## 시험 자료와 기준

정식 Flyway로 만든 별도 H2 메모리 DB에 합성 제품을 넣는다. 제품 사양은 메모리 32GB, 조회 기준일은 2026-11-01로 고정한다. 현행 `LISTING_HISTORY_ENABLED=true` 경로인 `JdbcListingHistoryReader`·허용 자료 구성·Q&A 서비스·모델 연결·결과 검증은 실제 구현을 사용한다. 이 Reader는 본문을 읽지 않고 이력 유형·날짜·상태·정정 여부만 전달한다. Redis의 실행권만 시험 대역이며 로그인·CSRF·요청 횟수·비동기 작업 처리 검사는 기존 HTTP·Redis 테스트가 담당한다.

| 구분 | 시험 기록/질문 | 통과 기준 |
|---|---|---|
| Q&A 사양 | 현재 메모리 | 32GB와 실제 사양 근거 |
| Q&A 정정 | 2026-09-18 부품 교체로 정정 | 최신 날짜·정정된 이력 근거, 세부 부품 확인 불가, 과거 감사 원문 제외 |
| Q&A 무효 | 무효 처리된 수리 | 무효임을 설명하고 실제 수리로 단정하지 않음 |
| Q&A 미검토 | 부품 교체 유형만 공개 | 부품을 추측하지 않고 미검토/확인 불가 표시 |
| Q&A 빈 이력 | 등록된 수리 이력 없음 | 기록으로 확인 불가, 무수리·무고장 단정 금지 |
| Q&A 보증 누락 | 보증 만료일 없음 | 확인 불가, 보증 유효 단정 금지 |
| Q&A 복합 질문 | 메모리와 보증 질문, 보증일 없음 | 메모리 32GB와 사양 근거 유지, 보증만 미확인 |
| Q&A 혼합 이력 | 메모리·유효 점검·무효 수리 함께 질문 | 사양·유효 점검 날짜 유지, 무효 수리의 실제 발생 단정 제외 |
| Q&A 보증 만료 | 2025-02-12 만료일 | 등록 만료일과 만료 상태, 보증 근거 |
| Q&A 범위 밖 | 구매 추천 | 서버의 범위 안내, 모델 조회 도구 호출 없음 |
| 카드 요약 4종 | 정정·무효·미검토·빈 이력 | 1~2문장·90자 이내, 등록된 제품 특징, 숨겨진 본문·과거 원문 미포함 |

시험에서 공개 검토 완료로 만든 이력은 합성 fixture뿐이다. 현재 Reader에서는 이 표시가 있어도 본문을 읽지 않으므로 정정된 키보드 이름을 AI가 알면 실패다. 실제 DB의 `public_text_reviewed`를 임의로 바꾸거나 미검토 본문을 외부 AI에 보내지 않는다. 과거 정정 원문과 비공개 부품명에는 합성 식별 문자열을 넣어, 허용 자료에서 빠지는지도 검사한다. 검토된 본문을 반환하는 `ListingHistoryAdapter`와의 선택·연동 계약은 별도로 맞춰야 한다.

## 실행

`ProductAiLiveQualityTest`는 아래 두 환경변수가 있어야 실행한다. 키는 서버용 환경변수로만 전달하고 소스·실행 인자·로그·보고서에 적지 않는다. `.env`에 적은 값이 PowerShell 환경변수에 자동으로 생기지는 않는다.

```powershell
$env:AI_LIVE_QUALITY = 'true'
$env:AI_LIVE_API_KEY = $env:GEMINI_API_KEY
$env:AI_LIVE_MODEL = 'gemini-3.5-flash-lite'
try {
    .\gradlew.bat test --tests org.example.springtestci.ai.ProductAiLiveQualityTest --rerun-tasks
} finally {
    Remove-Item Env:AI_LIVE_API_KEY,Env:AI_LIVE_QUALITY,Env:AI_LIVE_MODEL -ErrorAction SilentlyContinue
}
```

JDK 17과 사용 가능한 키가 필요하다. 모델을 바꾸면 `AI_LIVE_MODEL`도 바꾸고 결과를 따로 확인한다. 전체 14사례는 정상 진행 시 최대 22회의 생성 요청을 사용하며 공급자 요금·할당량이 적용된다. 기본적으로 사례 사이에 10초 간격을 두며 `AI_LIVE_DELAY_MS`로 0~60,000ms 범위에서 바꿀 수 있다. 429·공급자 장애가 생기면 이후 사례는 실행하지 않는다. 응답 지연·429·공급자 장애·제외 사례는 내용 정확성 통과로 계산하지 않는다.

Q&A 변경만 확인하려면 위 실행 명령의 `--tests`를 `org.example.springtestci.ai.ProductAiLiveQualityTest.actualQuestionAnswersMatchRegisteredFacts`로 바꾼다. 이 경우 Q&A 10사례만 실행하며, 보고서의 계획 사례 수와 실제 실행한 사례 수를 구분한다.

영향받은 질문만 다시 확인할 때는 `AI_LIVE_QUESTION_CASES`에 `EXPIRED_WARRANTY,CORRECTED`처럼 열거형 이름을 지정한다. 지정하지 않으면 Q&A 전체를 실행한다. 일부 재실행 결과를 전체 사례의 단일 실행 성공으로 집계하지 않는다.

`AiQualityTestContext`가 업무 DataSource·Hikari pool·Flyway URL/계정을 같은 새 H2 메모리 DB로 명시하고 `.env` import를 사용하지 않는다. `AiQualityTestContextTest`는 다른 메모리 DB와 잘못된 계정 설정을 상속한 상황에서도 지정한 시험 DB에서만 마이그레이션이 실행되는지 확인한다. 이 격리 검사는 외부 AI와 공용 DB를 사용하지 않는다.

## 결과 확인

- `build/reports/ai-live-quality/results.json`: 사례별 허용 입력, 답변, 실제 근거·조회 도구, 카드 문구, 검증 결과와 모델명
- `build/reports/tests/test/index.html`: JUnit 성공·실패·제외 결과

결과 파일은 합성 자료만 담고 Git에 올리지 않는다. `passed=false`인 사례는 외부 호출 실패인지, 서버 정책 거부인지, 답변 내용 불일치인지 구분한다. 자동 검사가 통과한 답변도 원천 기록과 문장 의미를 사람이 대조한다. 특히 무효 이력을 사실로 해석하는 표현, 누락된 정보의 추측, 불필요한 내부 용어를 확인한다.

이 검사는 고정된 대표 사례의 결과이며 전체 질문의 정확도나 장기 성공률을 뜻하지 않는다. 프롬프트·검증 정책을 수정할 때는 먼저 실패 사례를 보존하고, 수정한 사례와 영향받는 회귀 검사를 다시 실행한다.

## 2026-11-01 확인 결과

`gemini-3.5-flash-lite`로 Q&A 8종·카드 요약 4종을 재실행해 12사례 모두 통과했고, 답변·실제 근거·원천 자료를 대조했다. 정정 이력은 최신 날짜와 정정 표시를 사용하고 세부 부품을 추측하지 않았다. 무효 이력은 실제 수리로 취급하지 않았으며 보증일 누락은 확인 불가로 답했다. 카드 문구는 1~2문장·90자 이내였고 숨겨진 세부 내용이나 과거 감사 원문을 포함하지 않았다.

초기 실행에서 무효 이력의 올바른 답변까지 미검토 안내가 없다고 거부하는 문제와, 보증일이 없는데도 도구가 인용할 수 없는 `warranty` 키를 알려주는 문제를 발견해 수정했다. 무효 표시 누락·가짜 근거는 계속 거부하며, 이를 확인하는 HTTP 회귀 사례도 추가했다. 답변에 내부 필드명·유형 코드가 노출되지 않도록 프롬프트를 보완했다.

초기 정정 사례는 메타데이터 전용 Reader에서 세부 부품명까지 기대했던 시험 기준을 바로잡았다. 실제 답변이 본문을 누락한 오류로 집계하지 않았다. 마지막 카드 두 사례의 초기 429도 통과로 집계하지 않았으며, 호출 간격을 둔 재실행에서 확인했다. 공개 검토 본문의 Reader 선택·제공 계약은 이번 작업에서 변경하지 않았다.

`spotlessCheck test build`도 성공했다. 전체 1,019건 중 908건 통과, 기존 환경 조건 109건과 실제 모델 선택 실행 조건 2건 제외, 실패·오류 0건이다. 그중 Q&A HTTP 검사는 새 회귀 사례를 포함해 23건 모두 통과했다. 이 전체 검증은 외부 AI를 호출하지 않았으며, 위 실제 모델 12건 실행과 구분한다. 이번 검증에는 별도 PostgreSQL 실행이나 브라우저 시연을 추가하지 않았다.

## PR #71 리뷰 후 보완

- 무효 이력을 모델이 읽었다면 근거 인용에서 빠뜨려도 모델 문장을 출력하지 않는다. `ProductQuestionGroundedAnswer`가 조회한 사양·보증 만료일·이력 유형·날짜·상태로 설명을 구성하고 무효 안내를 유지한다. 유효한 기록과 사양도 함께 표시하며 자유 입력 본문·정정 원문은 재사용하지 않는다. 근거가 20개를 넘으면 일부 표시임을 안내하고, 문구가 2,000자를 넘으면 안내와 실제 근거 목록으로 대체한다.
- 보증 도구의 미확인 안내를 보증 정보에만 적용한다. 보증일이 없는 메모리·보증 복합 질문에서도 사양 근거를 유지한다.
- 실제 모델 시험의 업무 DB와 Flyway 연결을 동일한 새 H2 메모리 DB로 고정했다. 별도의 메모리 DB와 잘못된 연결 계정을 상속한 시험에서 대상 DB에만 마이그레이션이 실행되는지 검증한다.
- 실제 모델 검사에서 날짜가 맞아도 `2025년 2월 12일`의 숫자 표기 때문에 거부되던 사례를 추가로 확인했다. 실제 조회한 날짜만 ISO 표기로 정규화하며, 등록되지 않은 날짜 조합·달력에 없는 날짜는 계속 거부한다.

실제 Gemini Q&A 10종을 실행한 뒤 영향을 받는 사례만 재검증했다. 무효 이력·사양과 유효/무효 혼합 이력·보증 없는 복합 질문을 확인했고, 날짜 수정 후 정정·미검토·복합 질문과 보증 만료 사례를 다시 확인했다. 마지막 보증 검사는 만료일을 문장에 반드시 반복하는 대신 답변의 만료 상태와 실제 근거의 만료일·기준일을 함께 검사한다. 합친 사례별 최종 확인은 10종 모두 통과했으며 한 번의 전체 실행 성공으로 집계하지 않는다. 변경하지 않은 카드 요약의 외부 호출은 반복하지 않았다.

리뷰 보완 후 `spotlessCheck test build` 성공: 전체 1,038건 중 927건 통과, 기존 환경 조건 109건과 실제 모델 선택 실행 조건 2건 제외, 실패·오류 0건이다. Q&A HTTP 36건, 서버 문구 구성 5건, 실제 Flyway·DataSource 격리 1건을 포함한다. 공용 DB 변경과 브라우저 시연은 수행하지 않았다.
