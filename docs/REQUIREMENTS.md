## **1. 개요**

Pastport는 전자제품의 구매·점검·수리·부품 교체·소유권 이전 기록을 제품 단위로 누적하고, 중고 거래 때 다음 소유자에게 넘겨주는 디지털 제품 여권 서비스다.

- **목표 흐름**: 제품 기록이 생기고 → 그 기록이 거래에 쓰이고 → 거래 후 다음 소유자에게 이어진다.
- **대상 제품**: 최종 목표는 전자제품 전반, MVP는 노트북만 구현한다. 제품 공통 정보와 제품군별 사양을 분리해 향후 제품군 확장을 지원한다.
- **설계 원칙**: 사용자가 아닌 **제품을 중심으로 이력**을 관리하고, 제품 이력과 소유자 개인정보를 분리한다. AI는 입력과 탐색을 보조할 뿐 최종 확정과 거래 판단은 사람이 한다.
- **기준 문서**: 서비스 소개, MVP 범위 설정, 초기 기획안(배경·구현 방향), 기술 스택 정리
- **우선순위**: P0 = 반드시 구현, P1 = P0 안정화 후 추가

### **1-1. 용어**

- **제품**: 등록된 전자제품 한 대. 소유자가 바뀌어도 같은 ID를 유지한다.
- **제품 여권**: 제품의 기본 정보, 사양, 누적 이력 및 증빙을 연결해 관리하는 디지털 기록.
- **소유권**: 제품과 현재 소유자 한 명의 관계. 소유자가 변경되어도 제품 ID와 누적 이력은 유지된다.
- **이력**: 제품에 발생한 사건 기록(구매, 점검, 수리, 부품 교체, 사양 변경, 소유권 이전)
- **문서**: 영수증·보증서·수리 명세서 등 제품 기록을 뒷받침하는 파일. 개인정보를 제거한 사본만 보관한다.
- **판매글**: 판매자가 작성을 마치고 게시하여, 판매글 조회 권한이 있는 사용자에게 보여주는 글.
- **임시저장본**: 작성 중인 판매글을 서버에 비공개로 저장한 글. 작성자이면서 현재 제품 소유자인 회원만 다시 열어 수정할 수 있다.
- **AI 제안문**: AI가 작성한 판매글 제목·본문의 추천 문구. 사용자가 적용·수정할 수 있으며, 생성하거나 적용하는 것만으로 서버에 저장되거나 게시되지 않는다.
- **공개 이력**: 판매글이 판매 중 또는 예약 중일 때, 해당 글의 조회 권한이 있는 사용자에게 제공하는 개인정보 없는 누적 핵심 이력.
- **외부 이전**: 다른 중고 거래 서비스나 개인 간 거래로 제품을 넘긴 뒤, Pastport의 링크·QR로 제품 소유자와 연결 기록을 새 소유자에게 넘기는 절차. Pastport에서 판매글이나 내부 거래를 새로 만들지는 않는다.

## **2. 사용자와 공개 범위**

| 역할 | 정의 |
| --- | --- |
| 비회원 | 로그인하지 않은 방문자 |
| 회원 | 로그인한 사용자 |
| 소유자 | 해당 제품의 활성 소유권을 가진 회원(판매 시 판매자) |
| 구매자 | 판매글에 구매 요청을 보낸 회원 |
| 소유권 이전 수신자 | 제품 소유권을 넘겨받을 회원. 내부 거래에서는 예약된 거래의 구매자이며, 외부 이전에서는 유효한 링크·QR로 진입한 뒤 이전 절차에서 확인된 회원이다. 제품 요약 확인과 수락은 요청의 유효성 및 수신자 권한을 서버가 검사한 후 허용한다. |
| 이전 소유자 | 소유권이 끝난 회원. 해당 제품의 관리 화면·비공개 이력·증빙을 조회할 수 없으며, 제품 수정·새 이력 등록·판매글 작성 권한도 없다. 개인정보가 제거된 누적 핵심 이력과 마스킹된 증빙 사본은 현재 소유자에게 이어진다. 증빙 사본의 삭제 제한은 DOC-06을 따른다. |
| 관리자 | ADM 요구사항에 따라 거래·취소·업무 변경 기록을 조회할 권한을 가진 회원. |

### **2-1. 역할별 접근 가능 정보**

| 정보 | 현재 소유자 | 그 외 로그인 회원 | 비회원 |
| --- | --- | --- | --- |
| 제품 기본 정보·사양·이미지 | 조회·수정 | 판매글의 공개 정보만 조회. <br>소유권 이전 수신자는 별도 권한으로 제한된 제품 요약 조회. | 판매글에서 공개 정보 목록만 조회. (세부내용 확인 불가) |
| 공개 이력 | 조회, 본인이 작성한 일반 이력만 수정 | 판매글의 공개 정보만 조회. | 상세 이력 조회 불가 |
| 비공개 이력 | 이전 소유자 기록을 포함한 누적 핵심 이력 조회. 이전 소유자의 기록은 수정·삭제 불가. | 불가 | 불가 |
| 문서 | 조회.<br>이전 소유자의 문서도 소유권 이전 완료 후 조회. | 불가 | 불가 |
| 소유자 개인정보 | 본인 정보만 조회 | 불가. 판매자 닉네임만 노출 | 불가 |
| AI 제품 이력 질의 - 챗봇 | 접근 가능한 제품 정보·현재 사양·누적 핵심 이력을 사용. 판매글 종료 후에도 이용 가능 | 판매글의 공개 정보·이력만 사용. 종료된 판매글에서는 이용 불가. | 불가 |

| 조건 | 추가로 허용되는 권한 | 제한 |
| --- | --- | --- |
| **해당 구매 요청·거래의 당사자** | 본인이 참여한 구매 요청·거래 상세 조회 | 거래 당사자라는 이유만으로 제품의 비공개 이력·증빙 사본 조회 권한을 부여하지 않는다. |
| **유효한 이전 요청의 수신자** | 제한된 제품 요약·이전 요청 조회 및 수락 | 수락 전 비공개 이력·증빙 사본 조회 불가. 이전 완료 후 현재 소유자 권한을 적용한다. |

### **2-2. 제품 이력의 공개 상태 (PUBLIC / PRIVATE)**

- **PUBLIC:** 판매글을 최종 게시하면 전환되어 이전 소유자의 기록을 포함한 누적 핵심 이력을 판매글에 공개한다.
- **PRIVATE:** 제품 이력의 기본 상태. 현재 소유자는 제품 관리 화면에서 조회할 수 있다. 임시저장·미리보기·AI 생성은 이력의 공개 상태를 변경하지 않는다.

| 판매글 상태 | 공개 여부 | 제공 범위 |
| --- | --- | --- |
| ACTIVE (판매 중) | PUBLIC | 판매글 목록·상세 제공 |
| RESERVED (예약 중) | PUBLIC | 목록에서 제외하고 기존 상세 조회는 유지 |
| SOLD (판매 완료) | PRIVATE | 일반 공개 목록·상세 제공 종료 |
| CANCELLED (판매 중지) | PRIVATE | 일반 공개 목록·상세 제공 종료 |

## **3. 기능 요구사항**

### **3-1. 회원·인증 (AUTH)**

- **AUTH-01 회원가입**

    - 이메일, 비밀번호, 닉네임으로 가입한다.
    - 이메일 형식, 비밀번호 규칙, 닉네임 길이를 검증하고, 중복 이메일은 거부한다.

        - 입력 오류가 있으면 해당 항목과 수정 안내를 제공한다.
    - 이메일 인증을 완료하면 회원가입이 완료된다.

        - 인증 완료 전 로그인할 수 없다.
        - 인증 요청 만료시 인증 메일을 재요청할 수 있다.
- **AUTH-02 로그인**

    - 이메일과 비밀번호로 로그인한다.

        - 인증 실패시  로그인 실패 안내를 제공한다.
    - 로그인에 성공하면 Access Token, Refresh Token을 HttpOnly 쿠키에 저장한다.
- **AUTH-03 토큰 재발급**

    - Access Token이 만료되면 Refresh Token 쿠키로 재발급한다.

        - 재발급 성공시 새로운 Access Token과 Refresh Token을 발급하고, 기존 Refresh Token은 즉시 폐기하여 재사용할 수 없도록 한다.
    - Refresh Token이 없거나 만료 / 변조 / 폐기된 경우 재발급을 거부하고 재로그인을 안내한다.
- **AUTH-04 로그아웃**

    - 로그인 쿠키를 만료시키고, 서버의 해당 Refresh Token도 즉시 폐기한다.
    - Access Token도 남은 유효 기간 동안 사용할 수 없도록 차단한다.

        - 차단된 토큰으로 회원 전용 기능을 요청시 인증 실패 응답(401)을 반환한다.
- **AUTH-05 내 정보**

    - 본인 프로필과 보유 제품 수를 조회한다.
    - 소유권 이전이 완료된 제품은 보유 제품 수에서 제외한다.
- **AUTH-06 접근 제어**

    - 제품 관리, 판매, 구매 요청, 이전 수락, AI 질의는 회원만 할 수 있다.

        - 서버는 요청마다 로그인 여부와 해당 기능에 필요한 제품 소유 여부, 거래 당사자 여부, 소유권 이전 수신자 자격을 검사한다.
        - 세부 권한은 역할별 접근 권한 표를 따른다.

### **3-2. 제품 (PROD)**

- **PROD-01 제품 등록**

    - 필수 / 선택 입력 사항을 입력해 등록한다.

        - 필수: 제품명, 제조사, 모델명, 시리얼 번호
        - 선택: 주요 사양, 최초 구매일, 보증 만료일
    - 등록자가 첫 소유자가 된다.
- **PROD-02 시리얼 중복 방지**

    - 제조사와 시리얼 번호를 정규화한 (manufacturer, serial\_number) 조합을 제품의 중복 식별 기준으로 사용한다.
    - 동일 조합의 제품은 중복 등록할 수 없다.

        - 중복 등록 요청 시 409 오류와 함께 “이미 등록된 제품입니다. 현재소유자에게 소유권 이전을 요청하세요.”라고 안내한다.
    - 시리얼 번호는 현재 소유자에게만 제공한다.

        - 공개 화면에서는 모델명·사양·제품 사진·서비스 제품 ID로 식별한다.
- **PROD-03 고유 식별**

    - 등록 제품마다 고유한 제품 ID를 부여한다.

        - 소유자가 변경되어도 동일한 제품 ID와 연결된 기록을 유지한다.
        - 소유권을 이전받은 제품은 새 제품으로 등록하지 않는다.
- **PROD-04 사양 관리**

    - CPU, RAM, 저장장치, GPU, 화면, OS, 배터리 상태를 관리한다.
    - 사양을 변경하는 부품 교체 이력이 확정되면 변경 전 후 사양을 기록하고, 현재 사양을 갱신한다.
- **PROD-05 이미지**

    - 제품 사진을 업로드 / 삭제하고 대표 이미지와 표시 순서를 정한다.
    - 문서가 아닌 제품 외관 이미지를 기록한다.
- **PROD-06 내 제품 목록**

    - 현재 소유한 제품 목록을 조회한다.

        - AUTH-05 내정보 에서 확인할 수 있다.
    - 각 제품의 보증 상태, 이력 수, 최근 기록을 제공한다.
    - 소유권 이전이 완료되어 더 이상 소유하지 않는 제품은 내 제품 목록에서 제외한다.
- **PROD-07 제품 상세**

    - 기본 정보, 현재 사양, 이미지, 보증 정보, 문서와 이력 타임라인을 한 화면에서 조회한다.
    - 다른 사용자에게 제공하는 정보의 범위는 역할별 접근 가능 정보를 따른다.
- **PROD-08 제품 정보 수정**

    - 현재 소유자는 제품명·최초 구매일·보증 만료일을 수정할 수 있다.
    - 변경 사유와 수정 기록을 남긴다.
    - 수리 일자 등 제품 이력에 속하는 정보의 정정·무효 처리는 HIST-06을 따른다.

### **3-3. 문서·AI 정보 추출 (DOC)**

- **DOC-01 문서업로드**

    - 소유자는 JPG·PNG·PDF 형식의 증빙 파일을 선택한다.

        - 원본은 브라우저에서 처리하고, 마스킹 확인을 완료한 사본만 서버에 업로드한다.
        - 파일 크기 제한은 최대 10MB로 한다.
- **DOC-02 개인정보 제외(마스킹)**

    - 실명·연락처·주소·이메일·카드/계좌/주문/거래 식별정보와 불필요한 식별 코드를 문서 이미지·OCR 결과·추출 JSON·파일명·메타데이터에서 제거한다.
    - 구매내역, 수리비 등 허용된 제품 사실과 개인정보를 구분하여 처리한다.
    - 사진은 가린 개인정보의 원문이 사본에 남지 않도록 처리한다.

        - PDF는 숨은 텍스트·메타데이터까지 제거한 사본 또는 페이지별로 마스킹된 이미지 사본으로 보관한다.
    - AI 마스킹 결과만으로 완료 처리하지 않는다.

        - 사용자는 결과를 확인하고, 누락되거나 잘못 가려진 영역을 직접 수정한 뒤 사본 저장을 확정한다.
    - 개인정보가 포함된 원본과 마스킹 전 OCR 결과는 서버 및 외부 AI로 전송하거나 저장하지 않는다.

        - 마스킹 확인·취소·화면 종료 시 브라우저에서 사용하던 임시 데이터와 파일 참조를 정리한다.
    - 외부 AI에는 마스킹 확인된 최소 데이터만 전송하며 처리 목적·전송 여부를 고지하고 동의를 받는다.
    - 외부 AI 분석에 동의하지 않아도 자동 마스킹·수동 수정·증빙 사본 저장은 이용할 수 있다.

        - 이 경우 제품 정보는 사용자가 직접 입력한다.
- **DOC-03 마스킹·분석 실패 및 재시도**

    - 자동 마스킹이 실패하거나 잘못 가려진 경우, 사용자는 현재 화면에서 선택한 원본을 이용해 다시 시도하거나 마스킹 영역을 직접 추가·수정할 수 있다.
    - 사용자가 확인한 마스킹 사본만 서버에 저장한다. 저장에 실패하면 해당 사본으로 저장을 재시도할 수 있다.
    - 화면 종료·새로고침 등으로 선택한 원본을 사용할 수 없게 된 경우에는 파일을 다시 선택하도록 안내한다.
    - 마스킹 사본 저장 후 AI 정보 추출이 실패하면, 저장된 사본으로 재시도하거나 제품 정보를 직접 입력할 수 있다. 원본을 다시 제출할 필요는 없다.
    - 저장된 사본에서 개인정보가 뒤늦게 발견되면, 추가 마스킹과 사용자 확인을 거쳐 사본을 교체한다.
    - 문서 재마스킹은 제품 이력의 정정·무효 처리와 구분한다.
- **DOC-04 검토·확정**

    - 문서 등록은 ‘마스킹 확인’과 ‘제품 정보 확정’을 별도 단계로 진행한다.
    - 사용자는 자동 마스킹 결과를 확인하고, 필요한 영역을 추가·수정한다.

        - 확인한 사본만 서버에 저장한다.
        - 마스킹 처리와 저장은 DOC-02를 따른다.
    - 이후 저장된 사본과 추출한 제품 정보를 함께 보여준다.

        - 외부 AI 분석에 동의하지 않은 경우에는 직접 입력할 항목을 보여준다.
        - 사용자가 내용을 검토·수정하고 확정한 정보만 제품 정보 또는 이력에 반영한다.
    - 사본 저장이나 AI 추출 완료만으로 제품 정보·이력을 자동 변경하지 않는다.
- **DOC-05 문서에서 제품 정보 추출**

    - 원본과 마스킹 검토용 이미지는 파일을 선택한 사용자가 현재 브라우저 화면에서만 확인한다.
    - 외부 AI 분석에 동의한 경우, AI는 사용자가 마스킹 확인을 완료한 사본에서 허용된 제품 사실만 추출한다.

        - 추출 대상은 제품명·모델명, 구매일·구매처·구매 금액, 보증기간, 수리일·수리 내용 등 이다.
    - 문서에서 확인되지 않은 항목은 미확인 상태로 표시하며 임의로 채우지 않는다.
- **DOC-06 저장**

    - 장기 보관 대상은 개인정보 마스킹 확인을 완료한 사본이다.
    - 현재 소유자는 본인이 업로드했고, 핵심 이력에 연결된 적이 없으며, 이전받은 사본이 아닌 파일만 직접 삭제할 수 있다.

        - 핵심 이력에 연결된 증빙과 이전받은 증빙은 직접 삭제할 수 없다.
        - 연결 해제로 삭제 제한을 우회할 수 없으며, 이전 소유자는 이전 완료 후 파일을 삭제할 수 없다.
        - 개인정보 누락은 DOC-03의 재마스킹으로 처리한다.
- **DOC-07 문서 조회 권한**

    - 마스킹 확인이 완료된 증빙 사본은 현재 소유자가 제품 관리 화면에서 열람하거나 다운로드할 수 있다.
    - 서버는 열람·다운로드 요청마다 로그인 여부, 해당 제품의 현재 소유권, 마스킹 확인 완료 여부를 검사한 뒤 파일을 전달한다.
    - 소유권 이전이 완료되면 새 소유자가 기존 증빙 사본을 조회할 수 있다. 이전 소유자의 새로운 열람·다운로드 요청은 거부한다.
    - 판매글 게시 여부는 증빙 사본의 조회 권한을 변경하지 않는다.

### **3-4. 이력 (HIST)**

- **HIST-01 이력 등록**

    - 현재 소유자는 구매·점검·수리·부품 교체·사양 변경 이력을 등록한다.
    - 소유권 이전 이력은 서버가 자동 생성하며, 사용자가 직접 등록할 수 없다.
    - ACTIVE 판매글이 있는 제품에 새 핵심 이력을 등록하면 개인정보 제외 여부 검증 후, 등록과 공개 타임라인 반영을 함께 처리한다.
    - 기존 AI 요약은 AI-03의 기준에 따른다.
- **HIST-02 이력 항목**

    - 이력 유형, 발생일, 제목, 내용, 수리·점검처 등을 기록한다.

        - 이력 유형에 따라 비용, 교체 부품 등을 추가로 기록한다.
    - 이력의 PUBLIC/PRIVATE 상태는 HIST-05의 핵심 이력 공개 정책에 따라 서버가 관리한다.

        - 사용자가 개별 공개 여부를 선택하지 않는다.
    - 개인정보와 구매 판단에 불필요한 거래 식별정보는 공개 데이터에서 제외한다.
- **HIST-03 문서 연결**

    - 각 이력에는 같은 제품에 등록되어 마스킹 확인이 완료된 증빙 사본만 연결할 수 있다.

        - 다른 제품의 문서와 마스킹 확인 전 파일은 연결할 수 없다.
- **HIST-04 타임라인**

    - 이력은 발생일 순으로 표시하고, 같은 날짜의 이력은 등록 시각 순으로 정렬한다.
    - 정정된 기록은 정정 표시와 사유, 현재 정정된 내용을 함께 보여준다.

        - 무효 처리된 이력은 사유와 무효 표시(취소선)를 남긴다.
    - 정정·삭제 처리 후에도 원래 이력의 존재를 숨기지 않는다.
- **HIST-05 핵심 이력 공개 정책**

    - 제품 이력은 공개 판매글이 없을 때 일반 방문자에게 비공개(PRIVATE)로 관리한다.
    - 현재 소유자는 공개 판매글 유무와 관계없이 이전 소유자의 누적 핵심 이력을 조회할 수 있다.

        - 이전 소유자가 작성한 기존 기록은 수정·삭제할 수 없다.
    - 판매글을 최종 게시하면 누적 핵심 이력을 이전 소유자의 기록까지 포함하여 개인정보 없는 공개 정보(PUBLIC)로 제공한다.
        - 제목·내용·수리·점검처·교체 부품·정정/무효 사유는 서버의 공개 필드 자동 검사를 거쳐 제공한다. ADMIN 수동 승인은 요구하지 않는다.
        - 공개 제외 정보가 감지된 필드는 표시하지 않으며, 이력 유형·발생일·상태·정정 또는 무효 여부와 나머지 공개 가능한 필드는 유지한다. 상세 제외만으로 판매글 게시를 제한하지 않는다.
        - 상세 원천이 연결되지 않았거나 공개 가능한 내용이 없으면 그 상태를 구분해 안내한다. 개인정보가 제거된 공개 상세는 판매글과 공개용 AI 입력에 즉시 반영한다. 자동 검사 범위와 한계는 `HISTORY_PUBLIC_TEXT_CONTRACT.md`를 따른다.
    - ACTIVE 판매글 중 추가·정정한 핵심 이력도 안전성 검증 후 즉시 반영한다.

        - 기존 AI 요약은 AI-03의 기준에 따른다.
    - RESERVED 판매글의 상세와 공개 이력은 계속 열람할 수 있다.
    - RESERVED 거래 중에도 실제로 발생한 수리·점검·부품 교체·사양 변경 이력을 등록할 수 있다.

        - 등록한 핵심 이력은 개인정보 제외 여부를 확인한 뒤 공개 타임라인에 즉시 반영한다.
        - 해당 이력에 따른 현재 사양의 자동 갱신도 함께 반영한다.
        - 구매자의 변경 내용 확인과 예약 유지 여부는 TX-05를 따른다.
        - 외부 소유권 이전 요청이 진행 중인 경우에는 사용자의 새 이력 등록을 제한한다.
    - SOLD/CANCELLED 판매글은 일반 방문자의 상세·이력·Q&A 접근을 종료한다.

        - 해당 제품에 ACTIVE 또는 RESERVED 판매글이 없으면 누적 핵심 이력을 PRIVATE로 전환한다.
        - 재판매시 새 판매글에서 이력을 공개하고, 종료된 판매글은 다시 공개하지 않는다.
    - 판매자는 개별 핵심 이력을 제외하거나 공개 여부를 변경할 수 없다.
    - 필수 공개 이력과 현재 판매 가격은 공개한다.
    - PRIVATE로 전환된 후에도 현재 소유자는 제품 관리 화면에서 이전 소유자의 기록을 포함한 누적 핵심 이력을 계속 조회할 수 있다.
- **HIST-06 정정 추적**

    - 잘못 등록한 이력은 정정 또는 무효 처리로 바로잡는다.

        - 직접 삭제해 기록의 존재를 없애지 않는다.
    - 현재 소유자는 본인이 작성한 일반 이력만 정정 또는 무효 처리할 수 있다.

        - 이전 소유자의 이력과 시스템이 생성한 소유권 이전 이력은 변경할 수 없다.
    - 확정된 정정·무효 처리에는 로그를 남긴다.

        - 로그에는 대상 기록, 변경 전후의 제품 사실, 사유, 처리자, 처리 시각이 포함된다.
    - RESERVED 판매글의 상세와 공개 이력은 판매글 상세 조회 권한이 있는 사용자에게 계속 제공한다.
    - 무효 이력의 존재와 사유는 표시하되, 수리·교체 횟수나 현재 사양 등 유효 사실의 계산에서는 제외한다.
- **HIST-07 자동 이력**

    - 소유권 이전 완료 시 소유권 이전 이력을 생성한다.

        - 이전 요청 생성 / 취소 / 만료만으로 이전 이력이 생성되지 않는다.
    - 같은 등록 / 이전 완료 처리가 반복되어도 자동 이력을 중복 생성하지 않는다.
- **HIST-08 이력 연속성**

    - 소유권 이전 완료 후 새 소유자는 이전 소유자들의 개인정보 없는 누적 핵심 이력을 조회한다.

        - 이전 소유자의 이력은 수정·삭제할 수 없다.
    - 이전 소유자가 등록한 마스킹 확인 완료 증빙 사본의 조회 권한도 새 소유자에게 이어진다.

        - 열람·다운로드는 DOC-07을 따른다.
        - 공개 판매글에는 증빙 사본의 이미지·다운로드 기능·문서 등록 여부를 표시하지 않는다.
    - 정정·무효 표시와 연결된 정정 기록도 제품에 이어지며 새 소유자는 이를 조회한다.
    - 이전 완료로 SOLD가 된 판매글의 일반 공개는 종료하지만 새 소유자의 누적 조회 권한은 유지한다.
    - 증빙 사본의 삭제·재마스킹은 DOC-06·DOC-03을 따른다.
    - 핵심 이력에 연결된 사본(연결을 제거해 삭제를 우회하는 경우 포함)과 이전받은 증빙 사본은 직접 삭제를 제한한다.

### **3-5. 판매글 (SALE)**

판매자는 제품 정보와 누적 핵심 이력을 바탕으로 판매글을 작성한다. 작성·임시저장·미리보기는 SALE-01·03·04, 이력 공개는 HIST-05, 게시 처리는 SALE-02를 따른다.

- **SALE-01 판매글 작성**

    - 현재 소유자는 보유 제품을 선택하고 제목·가격·제품 상태 등급(1-5등급)·설명을 작성한다.
    - 공개 가능한 제품 기본 정보와 현재 사양을 자동으로 채운다.
    - 제품에 등록된 사진 중 하나를 대표 사진으로 설정하고 노출 순서를 정한다.
    - 판매 가격은 1원 이상의 정수로 입력한다.
- **SALE-02 판매 이력 공개**

    - 판매글 게시에 성공하면 이전 소유자가 등록한 이력을 포함한 제품의 누적 핵심 이력을 공개한다.

        - HIST-05의 이력 공개 정책을 참고한다.
    - 판매글의 증빙 문서 표시 제한은 HIST-08을 따른다.

        - 문서에서 추출하여 사용자가 확정한 제품 정보와 핵심 이력은 각 공개 정책에 따라 제공한다.
    - 판매글 게시에 성공하면 ACTIVE 등록·누적 핵심 이력 공개·사용한 임시저장본 삭제를 함께 처리한다.
- **SALE-03 판매글 임시저장**

    - 현재 소유자는 작성 중인 판매 내용을 서버에 비공개로 임시저장한다.
    - 필수 항목이 누락되어도 임시저장할 수 있다.

        - 입력된 값의 형식, 연결된 제품 / 사진과 사용자의 권한은 검사한다.
    - 사용자의 임시저장 또는 미리보기 요청 없이 임시저장본을 생성하지 않는다.

        - AI 생성이나 제안문 적용만으로 저장하거나 게시하지 않는다.
    - 임시저장된 내용을 최종 게시하면 임시저장 글은 삭제된다.
    - 임시저장 중 외부 거래를 통해 소유권 이전 시 연관된 임시저장글은 삭제된다.
- **SALE-04 게시 화면 미리보기**

    - 판매글이나 임시저장본의 작성자이면서 현재 소유자인 회원만 미리보기를 사용할 수 있다.
    - 미리보기 시 현재 작성 내용을 먼저 임시저장하고, 게시될 화면을 보여준다.
    - 공개 가능한 제품 정보·사진·누적 핵심 이력을 실제 게시 화면과 같은 형태로 보여준다.
    - 미리보기에서도 개별 핵심 이력을 선택하거나 제외할 수 없다.
    - 미리보기는 판매글을 게시하거나 이력의 공개 상태를 변경하지 않는다.
- **SALE-05 판매글 목록 및 상세**

    - 방문자는 제조사·판매 가격 범위·제품 사양 조건을 직접 선택·조합하여 조건에 맞는 ACTIVE 판매글을 조회할 수 있다.

        - 로그인한 회원은 판매글 상세에서 공개된 제품 정보·사진·설명·누적 핵심 이력·AI 요약을 조회한다.
        - 비회원은 목록만 조회할 수 있으며, 상세 화면과 상세 이력은 조회할 수 없다.
    - RESERVED·SOLD·CANCELLED에서는 새 채팅방을 만들 수 없지만, 기존 참여자는 대화를 계속할 수 있다.
    - ACTIVE, RESERVED 판매글의 AI 챗봇은 로그인한 회원에게 제공한다.
- **SALE-06 상태 관리**

    - 판매글은 ACTIVE(판매 중), RESERVED(예약 중), SOLD(판매 완료), CANCELLED(판매 중지)로 관리한다.
    - 판매글 작성자이면서 현재 제품 소유자인 회원은 ACTIVE 판매글의 제목·가격·제품 상태 등급·설명·공개 제품 사진을 수정할 수 있다.
    - 제품 기본 정보·사양·이력의 변경은 각각 PROD·HIST의 규칙을 따른다.
    - RESERVED 판매글의 일반 내용은 수정할 수 없다. 실제 발생한 핵심 이력의 등록·공개와 구매자 확인은 HIST-05·TX-05를 따른다.
    - SOLD·CANCELLED 판매글은 수정하거나 다시 공개할 수 없다. 재판매하려면 새 판매글을 작성한다.
    - 상태 변경 조건과 처리는 TX-04\~06·OWN-01을 따른다.
- **SALE-07 게시·이전 제약**

    - 하나의 제품에는 ACTIVE 또는 RESERVED 판매글 최대 한 개만 허용한다.

        - 종료된 판매글은 기록으로 보존한다.
    - 진행 중인 거래나 소유권 이전 요청이 있는 제품은 새 판매글을 게시할 수 없다.
    - ACTIVE 또는 RESERVED 판매글이 있는 제품은 외부 소유권 이전 요청을 생성할 수 없다.

        - ACTIVE 판매글이 외부 소유권 이전 신청을 원할 경우 CANCELLED를 먼저 진행한다.

### **3-6. 판매글 채팅·거래 (TX)**

- **TX-01 채팅 시작**

    - 로그인한 회원은 ACTIVE 상태인 타인의 판매글에서 채팅을 시작한다.
    - 판매글·문의자 조합으로 채팅방 하나를 유지하며, 다시 문의하면 기존 방으로 연결한다.
    - 판매자는 여러 구매자와 각각 채팅할 수 있다.

        - 새 방 생성 시 판매글의 ACTIVE 여부, 판매자의 제품 소유권을 검사한다.
    - RESERVED·SOLD·CANCELLED 판매글에서는 새 방을 생성하지 않는다. 기존 방은 원래 참여자가 계속 이용할 수 있다.
- **TX-02 채팅·거래 진행**

    - 채팅방의 판매자와 문의자만 텍스트 메시지를 조회·전송한다.
    - 채팅 화면에 판매글 상태와 구매 요청·거래 진행 상태를 표시한다.
    - 진행 단계와 사용자 권한에 따라 구매 요청, 수락·거절, 취소, 양측 거래완료 확인 기능을 제공한다.
    - 열린 채팅에 새 메시지를 자동으로 표시하고, 본인이 확인하지 않은 메시지 유무를 표시한다.

        - 상대방의 읽음 여부는 공개하지 않는다.
    - 거래 완료·취소·판매 취소 후에도 기존 참여자는 채팅를 계속 이용할 수 있다. 제품의 새 소유자에게 기존 채팅를 승계하지 않는다.
    - 실제 거래 금액을 위한 별도 입력 항목은 제공하지 않으며, 채팅에서 금액을 추출해 거래 금액으로 확정하지 않는다.
- **TX-03 구매 요청**

    - 문의자는 채팅 화면에서 해당 ACTIVE 판매글에 구매 요청을 보낸다.

        - 요청은 해당 채팅방의 판매글·판매자·문의자에 연결한다.
        - 판매자가 요청을 승인하면 예약 상태로 진입한다.
    - 같은 판매글에 대기 중인 요청은 회원당 한 개만 허용한다.

        - 기존 요청이 있으면 해당 요청의 상태를 보여준다.
    - 문의자는 본인의 PENDING 요청을 취소할 수 있다.

        - 요청 취소만으로 판매글 상태는 변경하지 않는다.
- **TX-04 예약 확정**

    - 판매자는 PENDING 구매 요청을 수락하거나 거절한다.

        - 수락: 요청은 ACCEPTED, 판매글과 거래는 RESERVED로 처리한다.
        - 거절: 요청은 REJECTED로 처리한다.
    - 판매글당 예약 거래는 한 개만 허용한다.

        - 다른 PENDING 요청은 유지한다.
        - 예약 중에는 새 채팅방·새 구매 요청·다른 요청 수락을 차단한다.
    - 예약 확정 된 문의자의 채팅방을 제외한 다른 채팅방에는 예약중 표시를 한다.

        - 채팅은 계속 할 수 있다.
    - 실제 합의·결제 금액을 별도로 입력받지 않는다.

        - 채팅에서 금액을 추출해 확정 거래 금액으로 저장하지 않는다.
- **TX-05 예약 취소**

    - 판매자와 구매자는 소유권 이전 완료 전까지 RESERVED 거래를 취소할 수 있다.
    - 예약 취소 시 관련 상태를 함께 변경한다.

        - 거래·수락된 구매 요청: CANCELLED
        - 대기 중인 소유권 이전 요청: CANCELLED, 링크·QR 무효화
        - 판매글: ACTIVE
        - 예약 취소 시 판매글은 ACTIVE로 돌아가며, 누적 핵심이력은 PUBLIC을 유지한다.
    - 다른 PENDING 구매 요청은 유지한다.

        - 취소된 요청으로 다시 거래하려면 새 구매 요청을 보낸다.
    - 취소 사유·수행자·시각을 기록한다.
    - 예약은 시간 경과만으로 자동 취소하지 않는다. 거래 완료, 당사자의 예약 취소 또는 판매글 취소 전까지 예약 상태를 유지한다.
    - 예약 중 새 핵심 이력이 등록되면 구매자에게 채팅 화면에서 변경 내용을 안내하고, ‘변경 확인·예약 유지’ 또는 ‘예약 취소’를 선택하게 한다.

        - 구매자가 변경 내용을 확인하기 전에는 거래 완료와 소유권 이전을 진행할 수 없다.
        - 구매자가 예약 유지를 선택하면 RESERVED 상태를 유지한다.

            - 변경 내용과 구매자의 확인 결과·시각을 기록한다.
        - 구매자가 예약 취소를 선택하면 본 항목의 예약 취소 규칙을 적용한다.

            - 등록된 이력과 그에 따른 현재 사양은 유지한다.
    - 판매글 자체를 취소하면 남은 PENDING 요청도 CANCELLED로 정리한다.

        - RESERVED 판매글은 예약 거래와 대기 중인 이전 요청도 함께 취소한다.
        - 판매글의 최종 상태는 CANCELLED로 처리한다.
        - 판매글 자체를 취소한 경우 이력의 비공개 전환은 HIST-05를 따른다.
- **TX-06 인수·거래 완료**

    - 선택된 구매자는 실제 제품 인수 후 제품 요약과 공개 이력을 확인하고 거래완료버튼을 누른다.

        - 로그인한 해당 구매자만 누를 수 있다.
        - 판매자 단독으로 거래를 완료할 수 없다.
    - 구매자·판매자 모두가 거래완료버튼을 누르면 거래가 완료된다.

        - 예약 중 새 핵심 이력이나 그에 따른 사양 변경이 반영되면, 변경 전에 받은 거래완료 확인은 무효 처리한다.
        - 구매자의 변경 확인이 완료된 후, 구매자·판매자 모두 최신 내용을 기준으로 거래완료를 다시 확인해야 한다.
        - 판매자가 거래완료버튼을 누르면 ‘소유권 이전이 진행됩니다.’ 안내한다.
    - 거래가 완료되면 시스템에서 이전 이력을 생성하고, 소유권 이전을 진행한다.
    - 완료된 판매글의 일반 공개 상세·Q&A·AI 요약 제공을 종료한다.

        - 제품 이력의 공개 범위는 HIST 정책을 따른다.
        - 새 소유자의 누적 이력 조회 권한은 유지한다.
- **TX-07 내 거래**

    - 본인이 참여한 채팅방을 기준으로 목록을 조회한다.

        - 구매 요청 전의 문의 채팅도 포함한다.
    - 목록에서 해당 채팅과 거래 상세로 이동한다.

        - 다른 문의자의 채팅과 거래 정보는 조회할 수 없다.
    - 종료된 판매글은 채팅방 식별에 필요한 최소 정보만 유지한다.

        - 판매글 상세 접근은 SALE 정책을 따른다.

### **3-7. 소유권 이전 (OWN)**

- **OWN-01 내부 거래 이전**

    - 구매자·판매자가 거래완료버튼을 누르면 소유권 이전이 진행된다.
    - 이전 시 다음을 하나의 트랜잭션으로 처리한다.

        - 거래: COMPLETED
        - 판매글: SOLD
        - 소유권 이전 요청: ACCEPTED
        - 제품 소유자 변경·소유권 이전 이력 생성
        - 남은 PENDING 구매 요청: REJECTED
        - 누적 핵심 이력: PRIVATE

            - 새 소유자는 현재 소유자 권한으로 누적 이력을 계속 조회할 수 있다.
    - 처리 시 거래 상태·이전 요청·당사자 권한을 확인하고, 구매자가 확인하지 않은 변경이 없는지, 양측의 거래완료 확인이 최신 이력과 사양을 기준으로 이루어졌는지 검사한다.

        - 일부 처리에 실패하면 전체를 반영하지 않는다.
        - 취소와 완료는 하나의 결과만 반영한다.
        - 반복 요청으로 이전과 이력을 중복 처리하지 않는다.
- **OWN-02 외부 이전**

    - 소유자는 외부 거래용 일회성 이전 요청을 생성하고, 링크 또는 QR로 전달한다.

        - 링크·QR이 노출되지 않도록 경고 메시지를 띄운다.
    - ACTIVE·RESERVED 판매글이나 진행 중인 예약 거래가 있는 제품은 외부 이전 요청을 생성할 수 없다.
    - 유효한 링크·QR로 진입한 로그인 회원과 판매자가 이력 이전을 승인한다.

        - 판매자가 승인하지 않으면 이전은 진행되지 않는다.
    - 수락 시 다음 처리를 진행한다.

        - 제품 소유자를 수신자로 변경
        - 소유권 이전 요청: ACCEPTED
        - 소유권 이전 이력 생성
- **OWN-03 만료·취소·재발급**

    - 링크와 QR은 동일한 일회성 토큰을 사용하며 발급 후 24시간 동안 유효하다.

        - 이전 요청 토큰은 원문 대신 해시로 저장한다.
    - 소유자는 수락 전까지 요청을 취소할 수 있으며, 만료·취소·수락된 요청은 다시 사용할 수 없다.
    - 제품당 유효한 이전 요청은 한 개만 허용한다.

        - 재발급 시 기존 PENDING 요청을 취소하고 새로운 요청과 토큰을 생성한다.
- **OWN-04 수신자 확인·수락**

    - 서버는 요청의 유효성과 수신자 권한을 확인한 뒤 제품 요약과 이전 요청 정보를 보여준다.

        - 내부 거래의 구매자는 판매글의 공개 이력도 확인한다.
        - 외부 이전은 수락 전 열람이 허용된 제한적 제품 요약만 제공한다.
    - 비회원은 로그인 후 이전 확인 화면으로 돌아온다.
    - 수신자는 내용을 확인하고 소유권 이전을 수락한다.

        - 본인 소유 제품은 수락할 수 없다.
- **OWN-05 이전 처리**

    - 수락 시 요청 상태·유효기간·수신자 권한을 다시 확인한다.

        - 현재 제품 소유자가 요청 발급자인지도 확인한다.
    - 소유자 변경과 관련 상태 변경을 함께 처리한다.

        - 일부 처리에 실패하면 전체를 처리 전 상태로 되돌린다.
    - 취소와 수락이 동시에 요청되면 하나의 결과만 반영한다.
    - 문서는 소유권 이전 완료 후 새 소유자에게 제공한다.
    - 같은 요청이 반복되어도 소유권 변경과 이전 이력은 한 번만 처리한다.
- **OWN-06 이전 후 권한**

    - 소유권 이전 완료 후 이전 소유자의 권한은 2장의 ‘이전 소유자’ 정의를 따르며, 새 소유자가 제품을 관리한다.
    - 새 소유자는 이전 소유자의 누적 핵심 이력을 조회하되 수정·삭제할 수 없다.
    - 이전 소유자의 판매글 임시저장은 이전 완료와 함께 삭제한다.
    - 마스킹된 제품 증빙 사본은 현재 소유자에게 승계하며, 승계 사본은 삭제를 제한한다.
    - 이후 새 소유자는 제품 화면에서 누적 이력과 정정·무효 표시를 계속 조회한다.

### **3-8. AI 판매글 추천**·상태 요약·질의응답 **(AI)**

- **AI-01 판매글 제목·본문 추천**

    - AI는 공개 예정 제품 정보로 제목·본문을 추천한다.
    - 누적 핵심 이력을 사용한다.

        - 이전 소유자의 핵심 이력도 포함하며 개별 이력을 고르지 않는다.
        - 문서는 입력에서 제외한다.
    - 구매 후 경과 기간을 실제 사용 기간으로 표현하거나 등록되지 않은 사용량·고장 여부를 추측하지 않는다.
    - 생성만으로 임시저장본을 저장하거나 판매글을 게시하거나 이력을 공개하지 않는다.
- **AI-02 AI 제안문 적용·편집**

    - 판매자는 AI가 제안한 제목·본문을 작성 화면에 적용하고 수정할 수 있다.
    - 적용은 화면 내용만 바꾼다.

        - 서버에 반영하려면 별도로 임시저장한다.

            - 임시저장은 SALE-03 정책을 따른다.
    - 저장 후 미리보기를 확인하고 최종 게시를 별도로 실행한다.

        - 최종 게시 전에는 이력을 공개하지 않는다.
- **AI-03 판매글 카드 핵심 요약**

    - AI는 ACTIVE/RESERVED 글의 공개 제품 정보와 누적 핵심 이력에서 제품 특징을 골라 1\~2문장, 전체 90자 이내로 요약한다.

        - 로그인 회원은 ACTIVE 판매글 목록 카드에서 두 줄 이내로 요약을 확인한다. 비회원 카드에는 로그인 안내만 표시한다.
        - 상세 화면은 원래 사양과 전체 타임라인을 제공한다. 판매자에게는 짧은 카드 요약의 상태·재생성 관리 기능을 제공한다.
        - 목록 조회는 저장된 요약을 함께 읽으며, 카드마다 이력 조회나 AI 생성을 실행하지 않는다.
    - 정정·무효 표시가 필요한 기록은 그 상태를 함께 설명한다.

        - 무효 이력을 실제 수리·교체로 표현하지 않으며, 원래 전체 이력은 상세 타임라인에서 확인할 수 있다.
    - 기록이 없다고 “수리한 적 없음”을 단정하지 않는다.
    - ACTIVE 또는 RESERVED 중 공개 정보가 변경되면 최신 자료로 다시 생성한다. 같은 제품 사실을 바탕으로 판매 조건만 바뀐 경우 이전 문구에 갱신 중 표시를 붙인다.

        - 제품 사실·공개 범위가 바뀌면 이전 문구는 숨긴다. 최신 자료가 생성되면 새 요약을 표시한다.
        - 생성 대기·실패 중에도 기본 상세와 타임라인은 제공한다.
    - SOLD/CANCELLED 판매글에는 공개 요약을 제공하지 않는다.

        - 종료 후 도착한 생성 결과도 제공하지 않는다.
- **AI-04 이력 질의응답(챗봇)**

    - 로그인한 회원은 해당 ACTIVE/RESERVED 판매글에서 해당 제품에 대해 질문한다.
    - AI는 판매글의 공개 제품 정보와 누적 공개 이력을 근거로 답한다.
    - SOLD/CANCELLED 판매글의 Q&A는 종료한다.

        - 현재 소유자의 제품 Q&A는 계속 허용한다.
    - 정정된 유효 사실을 근거로 답하고 무효 기록을 실제 수리·교체로 단정하거나 집계하지 않는다.
    - 비회원은 질문을 보낼 수 없다.
- **AI-05 실제 데이터 조회**

    - 답변에 필요한 제품·이력·보증 정보를 서버에서 조회한다.

        - Tool Calling으로 필요한 api를 명시적으로 호출할 수 있도록 프롬프트를 구성한다.
    - 서버는 질문자·현재 소유권·판매글 접근 범위를 확인한 뒤 허용된 정보만 조회한다.

        - 질문에 작성한 지시문이나 사용자 ID로 권한을 변경할 수 없다.
    - 조회 기능만 사용하며 게시·수정·삭제·공개 변경은 실행하지 않는다.
    - 공개용 AI 입출력은 SALE·HIST의 공개 제외 정책을 따른다.

        - 구매금액·수리비·시리얼 번호를 제외한다.
    - 결과 제공 전에도 권한과 자료의 최신성을 확인한다.

        - 권한이 없거나 최신 자료에 맞지 않는 결과는 제공하지 않는다.
- **AI-06 근거 표시**

    - 답변에는 실제로 조회한 근거를 표시한다.

        - 이력: 해당 이력의 유형·발생일·ID
        - 사양: 등록된 제품 사양
        - 보증: 확정된 보증 정보·조회 기준일
    - 조회하지 않은 기록이나 가짜 이력 ID를 근거로 표시하지 않는다.
    - 응답 직전에 권한을 다시 검사하며 접근할 수 있는 이력만 제공한다.
- **AI-07 답변 범위**

    - 근거가 없으면 "등록된 기록으로는 확인할 수 없다"고 답한다.

        - 기록이 없는 것을 "수리한 적 없다"로 단정하지 않는다.
    - 정정된 최신 유효 내용을 기준으로 설명한다.

        - 무효기록은 실제 수리·교체 횟수와 현재 사양 계산에서 제외한다.
    - 구매 후 경과 기간을 실제 사용 기간으로 표현하지 않는다.

        - 등록되지 않은 사용량이나 고장 여부를 추측하지 않는다.
    - 구매 추천·비추천, 가격 평가, 품질·안전성·정품 판정을 하지 않는다.

        - 해당 질문에는 판단할 수 없음을 안내하고 확인 가능한 기록을 정리한다.
- **AI-08 AI 처리 실패**

    - AI 처리가 실패해도 제품·이력·판매글 기능은 계속 이용할 수 있다.
    - 실패 안내와 재시도 기능을 제공한다.
    - 판매글 제안 생성이 실패해도 제목·본문을 직접 작성할 수 있다.

### **3-9 관리자(ADM)**

관리자는 거래 진행 상황과 업무 변경 기록을 확인한다. 인증·접근 보호는 AUTH·SEC의 공통 규칙을 따른다.

- **ADM-01 관리자 접근**

    - 관리자 권한을 가진 회원만 관리자 화면과 기능을 이용할 수 있다.
    - 서버는 관리자 요청마다 로그인 여부와 관리자 권한을 검사한다.
    - 일반 회원은 URL이나 API로 직접 요청해도 관리자 기능을 이용할 수 없다.
- **ADM-02 거래·취소 기록 조회**

    - 관리자는 거래 목록과 상세를 조회한다.
    - 거래 상태, 연결된 제품·판매글 ID, 당사자 회원 ID와 예약·완료·취소 시각을 확인한다.
    - 취소된 거래의 사유·수행자·처리 시각은 TX-05에 따라 표시한다.
- **ADM-03 업무 변경 기록 조회**

    - 관리자는 SEC-08에서 정한 업무 변경 기록을 조회한다.
    - 대상 ID, 행위, 처리 주체, 결과와 처리 시각을 확인한다.
    - 이력 정정·무효 처리의 변경 내용과 사유는 HIST-06을 따른다.
- **ADM-04 조회 범위와 기록 보호**

    - 관리자 기능의 조회 범위는 ADM-02·03의 업무 정보로 한정한다.
    - 관리자 권한만으로 비공개 증빙 사본이나 채팅 본문의 열람 권한을 부여하지 않는다.
    - 관리자 화면에서 업무 기록과 거래 상태·소유권·이력 원기록을 직접 수정하거나 삭제할 수 없다.

## **4. 정책**

#### **수락 후 취소 처리 규칙**

Pastport는 결제·환불을 처리하지 않는다. 거래 당사자는 채팅으로 거래 일정을 조율하고, 소유권 이전 완료 전까지 예약을 직접 취소할 수 있다. 예약 유지 시간에 제한을 두거나 시간 경과만으로 자동 취소하지 않는다.

1. **즉시 취소**: 판매자·구매자 모두 수락 후 거래 완료 전까지 바로 취소할 수 있다. 판매글은 판매 중으로 돌아간다.
1. **사유 필수**: 취소하는 사람은 내 사정(일정·마음 변경), 상대 요청으로 합의, 상대 연락 두절, 제품 상태가 설명과 다름 중 하나를 고른다. 사유는 상대의 "내 거래" 화면에 표시된다.
1. **귀책 기록**: 사유로 취소가 누구 쪽 사정인지 저장한다. 사용자별 "내 사정" 취소 횟수는 P1 거래 후기·평가(P1-12)에서 신뢰 지표로 쓴다.
1. **예약 유지**: 예약은 시간 경과만으로 자동 취소되지 않는다. 예약 종료와 관련 상태 처리는 TX-05·TX-06·OWN-01을 따른다.
1. **판매자 보호**: 수락해도 다른 대기 요청은 거절하지 않고 남겨둔다. 예약 취소 시 판매자는 남은 요청 중 하나를 바로 수락할 수 있다.

## **5. 비기능·보안 요구사항**

기능별 권한·공개 범위·상태 변경은 2장과 3장의 해당 요구사항을 기준으로 한다. 이 장은 모든 기능에 적용할 보안·품질 기준을 정한다.

- **SEC-01 인증과 접속 보호**

    - 회원 전용 요청은 서버가 인증 정보의 유효성을 검사한다.

        - 로그인·재발급·로그아웃 처리는 AUTH-02\~04를 따른다.
    - 비밀번호는 비밀번호 저장용 단방향 해시로 보관한다.

        - 배포 환경의 사용자 접속은 HTTPS를 사용하고, 인증 쿠키에는 HttpOnly·Secure·SameSite 보호 설정을 적용한다.
    - 쿠키로 인증하는 상태 변경 요청은 CSRF 검증을 거친다.

        - CSRF 토큰의 발급·전달·검증 방식은 구현 명세에서 정한다.
    - DB 접속 비밀번호·JWT 서명 키·외부 AI API 키는 소스코드나 브라우저에 노출하지 않고 서버 설정으로 관리한다.
- **SEC-02 기능별 접근 권한 검사**

    - 서버는 각 요청에서 대상 제품·이력·문서·판매글·거래·이전 요청에 대한 권한을 검사한다.

        - 기준은 2장의 역할별 접근 표와 AUTH-06을 따른다.
    - 화면에서 버튼을 숨기는 것만으로 권한을 제한하지 않는다. 다른 대상의 ID를 입력해 요청해도 권한이 없으면 거부한다.
    - 채팅 요청의 참여자 권한과 메시지 발신자는 서버의 인증 정보를 기준으로 확인한다.

        - 채팅방별 조회·전송·승계 제한은 TX-01·02를 따른다.
- **SEC-03 파일 검증과 접근 보호**

    - 서버는 업로드 권한, 허용된 파일 종류, 실제 파일 형식, 크기 제한을 검사한다.

        - 확장자나 브라우저가 보낸 형식 정보만으로 파일을 허용하지 않는다.
    - 파일 저장소는 비공개로 유지한다. 파일 제공 시 대상 파일의 연결 제품과 요청자의 접근 권한을 검사한다.
    - 증빙은 DOC을 따르며, 판매글 사진의 제공 범위는 SALE을 따른다.
- **SEC-04 개인정보와 대화 내용 보호**

    - 판매글·공개 이력·공개용 AI 입출력에는 개인정보와 공개 제외 정보를 노출하지 않는다

        - 범위는 PROD-02·HIST-02·HIST-05·AI-05를 따른다.
    - 증빙 문서의 개인정보 제거·저장·열람은 DOC-02\~07을, 운영 로그의 기록 제한은 NFR-07을 따른다.
    - 채팅 본문은 AI 입력·제품 이력·소유권 이전 승계 자료에 포함하지 않는다
- **SEC-05 입력 검증과 안전한 표시**

    - 서버는 기능별로 필수 여부, 형식, 길이, 허용 범위와 연결 대상의 유효성을 검사한다.

        - 필수 항목이 비어도 가능한 임시저장에는 SALE-03을 적용한다.
    - 사용자 입력과 AI 응답을 화면에 표시할 때 임의의 HTML·스크립트가 실행되지 않도록 처리한다.

        - DB 조회에는 사용자 입력을 명령문으로 직접 결합하지 않고 매개변수로 전달한다.
- **SEC-06 AI 도구와 지시문 제한**

    - 질문·판매글·제품 이력·문서 안의 지시문을 시스템 명령이나 접근 권한의 근거로 사용하지 않는다. AI 도구 호출의 대상과 권한은 서버가 검사한다.
    - AI가 호출하는 서버 도구는 허용된 조회 기능으로 제한한다.

        - 게시·수정·삭제·공개 변경·소유권 이전을 실행하는 도구는 제공하지 않는다.
    - AI가 제안하거나 추출한 정보를 실제 데이터에 반영하는 절차는 DOC-04·AI-02를 따른다.
- **SEC-07 소유권 이전 토큰 보호**

    - 링크·QR에는 예측하기 어려운 일회성 토큰을 사용하고, 서버에는 원문 대신 해시를 저장한다.

        - 유효성·만료·취소·재발급·수락 처리는 OWN-03\~05를 따른다.
- **SEC-08 변경 기록**

    - 확정된 판매글 게시, 이력 정정·무효 처리, 예약 취소, 거래 완료, 소유권 이전, 이력 공개 상태 변경에 처리 주체, 대상 ID, 행위, 결과와 시각을 기록한다.

        - 처리 주체는 회원 ID 또는 시스템으로 구분한다.
    - 정정 사유·변경 전후 사실은 HIST-06, 취소 사유는 TX-05를 따른다. 변경 기록은 일반 사용자가 수정·삭제할 수 없으며, 조회에는 권한 검사를 적용한다.
- **NFR-01 조회 성능과 처리 진행 표시**

    - 제품·판매글 목록과 상세 조회 API는 측정 요청의 95%가 1초 이내에 응답하는 것을 목표로 한다.

        - AI 처리와 파일 전송 시간은 별도로 측정한다.
    - 배포 환경, 동시 사용자 수, 데이터 건수, 대상 API와 측정 방법을 테스트 전에 정하고 결과와 함께 기록한다.

        - 목록 조회에는 페이지 구분과 요청당 조회 수 제한을 적용한다.
    - AI·파일 처리 중에는 진행 상태를 표시하고, 대기 중에도 처리 완료를 기다릴 필요가 없는 화면 조회·기능은 이용할 수 있게 한다.
- **NFR-02 동시·반복 요청과 데이터 일관성**

    - 동시 요청에도 SALE-07·TX-04·OWN-03에서 정한 판매글·예약 거래·이전 요청의 생성 제약을 지킨다.
    - 거래 완료·취소·소유권 이전에 필요한 DB 변경은 모두 함께 반영하며, 일부 실패하면 전체를 되돌린다.

        - 세부 처리는 TX-05·OWN-01·OWN-05를 따른다.
    - 완료·취소가 동시에 요청되면 하나의 결과만 확정하며, 반복 요청으로 소유권 이전이나 자동 이력이 중복 생성되지 않게 한다.
- **NFR-03 지원 환경**

    - Chrome·Edge·Safari의 최신 안정 버전과 휴대폰·PC 화면에서 주요 기능을 검증하고, 확인한 버전과 환경을 기록한다.
    - 휴대폰에서 QR로 진입한 뒤 로그인하고 이전 확인 화면으로 돌아오는 흐름을 검증한다.
- **NFR-04 완료 기준과 자동 검증**

    - 코드 통합 전 형식 검사·자동 테스트·빌드를 통과해야 한다.

        - 최종 완료 검증은 6장의 MVP 완료 기준을 따른다.
    - CSRF 검증 실패 시 요청 차단, 문서 원본·마스킹 전 OCR 결과의 서버 및 외부 AI 미전송, 소유권 이전 전후 증빙 접근 권한을 검증한다. 상세 테스트 사례는 테스트 전략에서 관리한다.
    - 권한 없는 접근, 이력 공개 전환, 동시 예약 수락, 반복 이전 요청, 취소·완료 경합과 실패 시 데이터 복구를 자동 테스트로 검증한다.
- **NFR-05 과도한 요청 제한**

    - 로그인, 인증 메일 요청, 파일 업로드, AI 호출, 소유권 이전 수락과 채팅 전송에 기능별 요청 횟수 제한을 적용한다.
    - 제한 기준, 집계 대상과 제한 해제 시간을 구현 명세에 정한다.

        - 한도를 넘으면 해당 요청을 거부하고 다시 시도할 수 있는 시점을 안내한다.
- **NFR-06 실패 안내와 재시도**

    - 화면은 처리 중·성공·실패를 구분한다. 오류 응답은 공통 형식으로 제공하고, 사용자가 수정하거나 재시도할 방법을 안내한다.
    - 사용자에게 내부 오류 추적 내용, DB 접속 정보나 비밀 키를 노출하지 않는다.
    - 외부 AI 호출에는 응답 대기 시간 제한을 둔다.

        - 실패·시간 초과 시 재시도와 직접 입력 등의 대체 방법은 DOC-03·AI-08을 따른다.
- **NFR-07 운영 로그**

    - 운영 오류의 종류·결과·발생 시각·요청 ID를 기록한다.
    - 민감정보는 로그에서 제외하며, 대상 범위는 SEC-01·04·07과 DOC-02를 따른다.
    - 업무 변경 기록은 SEC-08을 따른다.
    - 로그는 비공개로 관리하고, 접근 권한·보관·삭제 기준은 운영 전에 정한다.
