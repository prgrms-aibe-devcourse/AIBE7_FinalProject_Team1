# 문서 마스킹 자동 가리기: 사진 영수증을 못 가리는 문제

대상 코드: `src/main/resources/static/js/doc-mask-auto.js` (브라우저 OCR, tesseract.js 5.1.1, 한글+영어)
테스트: `src/test/js/doc-mask-auto.test.mjs`

## 증상

선명해 보이는 영수증 사진인데도 "자동으로 찾은 개인정보가 없어요"가 나오거나, 이름·이메일이 가려지지 않는다.

## 원인 확인 방법

첨부된 영수증 3장(애플 구매 영수증 사진, 애플 보증서, 이마트 영수증)을 같은 설정으로 OCR에 돌려 읽힌 글자와 가릴 영역을 비교했다.
확인에 쓴 이미지는 채팅에 올라온 축소본(437×583, 512×512)이라 실제 업로드 원본보다 결과가 나쁠 수 있다.

## 원인

| # | 원인 | 근거 |
|---|------|------|
| 1 | 페이지 분할 모드를 `3`으로 고정. 기울어지거나 그림자가 진 사진에서는 글자를 거의 못 찾는다 | 애플 영수증 사진: 모드 3은 3배로 키워도 읽힌 단어 0~1개, 모드 6은 147개. 폴백이 없어 0개여도 재시도하지 않았다 |
| 2 | 작은 이미지를 키우지 않고 그대로 OCR에 넣음 | 이마트 영수증(512px)은 글자가 뭉개져 대부분 못 읽고, 3배로 키우면 일부만 읽힌다 |
| 3 | 라벨 없는 이름은 규칙에 없음 | 이름 규칙은 `성명`, `구매자` 같은 라벨 뒤의 글자만 본다. 애플 영수증은 이름이 라벨 없이 날짜 아래에 있다 |
| 4 | 사업자등록번호가 계좌번호로 오탐 | `206-86-50913`이 계좌번호 규칙(숫자 10자리 이상, 3묶음)에 걸린다 |
| 5 | 읽은 글자가 깨지면 정규식이 맞지 않음 | 모드 6에서도 이메일이 `quiefasol® aver Lo n`처럼 깨져 읽혔다 |

이마트 영수증과 보증서는 개인정보가 거의 없다(상점 전화·사업자번호·바코드·일련번호). "못 가렸다"기보다 가릴 대상이 적은 문서다.

## 적용한 수정

1. **전처리**: 긴 변이 1600px보다 작으면 최대 3배까지 키우고, 흑백·대비(`grayscale(1) contrast(1.3)`)를 적용한다. 찾은 좌표는 원본 크기로 되돌린다. `ctx.filter`를 지원하지 않는 브라우저는 확대만 적용된다.
2. **모드 폴백**: 모드 3으로 읽은 단어가 20개 미만이거나 가릴 곳이 없으면 모드 6으로 다시 읽고, 겹치는 상자(절반 이상)는 합친다. 모드 3이 충분히 읽고 가릴 곳도 찾았으면 다시 읽지 않는다.
3. **라벨 없는 이름**: 이메일 바로 위 줄이 한글 2~4자뿐이고 줄 간격이 글자 높이의 1.5배 이내면 이름으로 가린다.
4. **사업자등록번호 제외**: `000-00-00000` 형태는 계좌번호로 보지 않는다.
5. **일련번호 필수 가리기**: `일련번호`·`시리얼(번호)`·`Serial No`·`S/N` 라벨 뒤의 영문·숫자 6자 이상 값을 가린다(값에 숫자가 없으면 일반 단어로 보고 제외). 라벨은 가리지 않고 값만 가린다. 애플 영수증의 `CXV5J3Y2RD`, 보증서의 `C02TQZ…` 형태가 대상이다.

## 검증

- 단위 테스트 8개 추가(이메일 위 이름, 이름 오탐 방지, 사업자번호, 모드 폴백 3종, 일련번호 2종). JS 테스트 전체 171개 통과.
- 실제 OCR 확인: 위 축소본 기준으로는 애플 영수증 사진에서 여전히 가릴 영역이 나오지 않았다. 이 영수증은 이름·이메일이 깨져 읽혀서 규칙이 맞지 않기 때문이다. 이마트 영수증은 상점 전화로 보이는 한 곳만 잡혔다.
- 브라우저에서 원본 해상도 사진으로 직접 확인한 것은 아니다.

## 남은 한계와 확인할 것

- OCR 방식은 사진 품질에 따라 놓칠 수 있다. 직접 가리기와 업로드 전 사용자 확인은 계속 필요하다.
- 원본 해상도 영수증 사진으로 브라우저에서 한 번 더 시험해 보는 것이 좋다.
- 모드 6 재시도로 분석 시간이 늘 수 있다. 진행률은 두 번째 읽기에서 0%부터 다시 시작한다.
- 이름 추정(3번)은 휴리스틱이라 이메일 위 줄이 우연히 한글 2~4자인 경우 잘못 가릴 수 있다. 가린 뒤 사용자가 해제할 수 있다.
- 일련번호 라벨이 `일련빈호`처럼 깨져 읽히면 값을 못 찾는다. 이 경우는 직접 가리기가 필요하다.
- 이메일이 깨져 읽히는 경우를 위한 보완(예: 느슨한 이메일 패턴)은 오탐 위험이 있어 이번에는 넣지 않았다.
